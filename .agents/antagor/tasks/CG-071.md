A package carries the gate command with the template tag in several files, and Antagor's checks hold it too. A package that follows Antagor's advice for mode fast drops the gate from its checks, so every copier update conflicts on that line. The remote gate already runs the full gate in CI before every tag.

1. The CI workflow is the only package file that writes the gate command with the template tag.
2. Antagor's config keeps the docstring check in its checks, the remote gate and heavy; it has no gate command.
3. The agents file, the coding standards and the readme name the gate as the rb-release check step of the CI workflow (run that command before a commit), without a copy of the command.
4. The package's CI test asserts that the workflow runs the gate of the template tag and that the agents file and the coding standards point to the workflow.
6. The existing-package reference says how to resolve that one conflict on the checks line: keep the package's own checks, drop the gate command.
5. The Standard's Release section describes the remote gate that runs before the tag; the skill and its references stop telling the reader to put or keep the gate line in Antagor's checks.

## Acceptance

- Given a package rendered from the template, When its files are searched for the gate command with the template tag, Then only the CI workflow has it, and Antagor's checks hold the docstring check and no gate command [check: sh scripts/check_template.sh]
- Given a package made from the previous release tag with the gate command in Antagor's checks, When copier update runs to this template, Then no conflict appears, the gate command is gone from the checks and the package's tests pass [check: sh scripts/check_template.sh]
- Given a package made from the previous release tag whose checks are fast-mode checks without the gate command, When copier update runs to this template, Then the only conflict is the checks line of Antagor's config, once, in this transition; resolved the way the existing-package reference says (keep the package's own checks, no gate command), the package's tests pass [check: sh scripts/check_template.sh]
- Given a rendered package, When its tests run, Then the CI test checks the workflow runs the gate of the template tag and the agents file and the coding standards point to the workflow [check: template/tests/test_ci.py]

## How to test

The template gate script: render the variants, update from the previous release tag with both kinds of checks, run each package's suite; the CI test of the package checks the files.
