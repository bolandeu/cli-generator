From CG-IDEA-004, the llmkit architect. Three things in one ticket, all small.

1. Template: `_param_meta` writes `x-rb-default` only when the default is not None, not callable and not (). Emit it always: the serialized value, or null when there is no default or it is computed at run time. Same for an argument. The key set of a param entry becomes fixed: name, required (arguments), arity, acceptedValues (choices), description, hidden, metadata[x-rb-type, x-rb-default, x-rb-multiple].

2. Standard, Describe section: name the per-parameter fields plainly, each with its mark:
   - `x-rb-type` — Mandatory, on every option and every argument; the value is a Typer type name from this closed list: boolean, str, int, float, choice, path, file, datetime, int range, float range. A new name in the list is an additive change.
   - `x-rb-default` — Mandatory and always present: the value, or null when the parameter has no default or it is computed at run time.
   - `x-rb-multiple` — Mandatory where it applies: present and true iff the parameter is repeatable or variadic; absent means single.
   - `hidden` — a hidden command, option or argument carries `hidden: true`; absence means visible. It is an OpenCLI field (the template has emitted it since v1.5.0 and the vendored schema accepts it).

3. Gate: a step that reads the package own `describe --json` and fails, naming the parameter, on a param entry without `x-rb-type`, with a type name outside the list, without the `x-rb-default` key, or with `x-rb-multiple` that is not true. Wire it into the gate as a named step next to `standard: docs`.

Vocabulary evidence (this machine, 7 CLIs): boolean 1485, str 873, int 357, choice 241, float 74, int range 34, path 23, file 1, datetime 1, float range 1.
