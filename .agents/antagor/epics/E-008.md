## Problem

The Standard's Describe section names x-rb-* only as 'tool names, env vars, data tables and views, external programs, skills'. The per-parameter fields and hidden are emitted by the template but never specified, so a consumer cannot tell a rule from an accident, and llmkit asked whether they were mandatory. The template also omits x-rb-default when the default is None, a callable or ().

## Goal

A consumer reads one describe --json and knows every option and argument without guessing: a type, a default (null when there is none), repeatability. The Standard names these fields and hidden; the gate refuses a document that breaks them.

## Acceptance (Given–When–Then)

- Given a package generated from the template, when its describe --json is read, then every option and argument carries x-rb-type from the documented vocabulary and an x-rb-default key (null when there is no default or it is computed at run time)
- Given a package whose document lacks a type or a default key, when the gate runs, then the describe step fails and names the parameter
- Given a hidden command, option or argument, when the Standard is read, then it says the document serializes hidden: true and that absence means visible

## Implementation decisions

- The Standard's Describe section names x-rb-type, x-rb-default, x-rb-multiple and hidden, each with its Mandatory or Recommended mark and the gate step that checks it.
- The template emits x-rb-default always, null when the default cannot be serialized.
