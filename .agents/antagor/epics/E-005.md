## Problem

Every generated package keeps its own copy of the output layer (envelope, guard, group, errors, version); fixes reach packages only through copier update with conflicts, and 7 of 16 packages already drifted. rb-cli-core 0.2.0 (CORE E-002) holds the layer as a library, but the template still copies it.

## Goal

A package with adopt_core=true imports the shared output layer from rb-cli-core (>=0.2,<0.3, runtime dependency from the gitea index); its own errors and human rendering stay in its files; every command prints and exits exactly as before. A package with adopt_core=false is untouched. The skill has the Update step for the switch; clidocs is the first package to take it.

## Acceptance (Given–When–Then)

- Given the same project rendered with adopt_core=false and adopt_core=true, When every command runs (help, --json, success, an expected error, an unexpected error, --version), Then stdout, stderr and the exit code are identical, and the help snapshots are the same files
- Given a project rendered with adopt_core=false, When it is compared with the same project from template v1.20.9, Then nothing changes
- Given a project rendered with adopt_core=true, When its files are read, Then the output layer, the errors module and the version module are thin modules importing the shared part from rb-cli-core, the package's own errors and human rendering are in the package, and pyproject has rb-cli-core>=0.2,<0.3 in dependencies (runtime) from the explicit gitea index
- Given a project on template v1.20.9 with adopt_core=true and its own CliError subclass, When copier update to this template runs (through the worker script, unattended), Then the shared copies are replaced, the package's own error still works with its code and exit code, and the gate passes; a conflict in a file the package edited is shown, not silently lost
- Given cli_name differs from package_name (rb_sitemap_xml / sitemap-xml), When the adopt_core=true project runs its commands, Then version, help and error actions name sitemap-xml and the distribution rb-sitemap-xml
- Given SKILL.md, When Update mode is read, Then a numbered step takes the output layer from the core with exact commands, says that a package which edited the shared part ports the edit to the core first (no local copy), and that a Renovate PR removing the copies stays red until that step is done

## Implementation decisions

- copier: adopt_core=true drops the shared output code and renders thin re-export modules in its place; the import paths that commands use stay the same, so command code does not change
- pyproject template: with adopt_core, rb-cli-core>=0.2,<0.3 moves from the dev group to runtime dependencies; the gate keeps rb-release check
- The package hands its identity (distribution name, command name) to the core once at start, in the generated entry point
- Template gate: a parity round (adopt_core false vs true on the same answers) and an update round from v1.20.9 with adopt_core=true

## Test seams

- The generated CLI's command line: stdout, stderr, exit code and help snapshots, adopt_core=false vs true, in sh scripts/check_template.sh
