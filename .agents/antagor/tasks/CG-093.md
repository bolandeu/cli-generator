## Problem

llmkit shipped v0.14.12 and v0.14.13 with `describe --json` answering `UNEXPECTED: AttributeError: TyperOption has no attribute 'type'` under a fresh `uv tool install`, and the gate was green. Two gaps let it through:

- the gate's wheel step installs exactly `uv.lock`'s set and never resolves;
- the fresh-install step resolves, but probes only `<cli> --version` and `<cli> --help`.

`describe` is the consumer contract (mcp builds tool schemas from it), so a broken describe must not reach a tag.

## Fix

In `Gate.check_fresh_install`, after `--help`, run `<cli> describe --json` on the freshly installed script and require a parseable envelope: JSON on stdout, `ok` not false, and a `command` object. A package without the Describe part (`describe` is an optional part) answers typer's "No such command" usage error — treat that as absent and keep the step green, naming it in the step's detail.

No new Step, no new rule for the package's author: one more call in a step that already exists.

## Test

Extend `gate/tests/test_release.py` with the two cases the acceptance names, using the flat-index fake dependency the existing fresh-install test already builds: the package keeps its `describe` working on the locked wheel and breaks it (a dependency's next minor removes a name `describe` imports) under a fresh resolution.

## Acceptance

- Given a package whose describe --json fails only under a fresh resolution, When the gate runs, Then the fresh install step fails and names the command [check: gate/tests/test_release.py]
- Given a package without the Describe part, When the fresh install step runs, Then it stays green and says the command is absent [check: gate/tests/test_release.py]

## How to test

level: the gate's own tests (uv run --directory gate pytest), plus one run of the gate on a package generated from the template; seam: the freshly installed console script, never the locked wheel's; data: the flat-index fake dependency the existing fresh-install test already builds

## Basis

Reuse the fresh install's own tool directory and console script; describe is already read by standard.check_params on the locked install — this is the same call on the fresh one
