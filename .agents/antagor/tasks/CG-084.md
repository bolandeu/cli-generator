The Human, 2026-11-08: CI is either remote or local, not both — and it is local. The template must stop rendering .gitea/workflows/ci.yml.

1. Remove template/.gitea/workflows/ci.yml.jinja and the answers that feed it (grep copier.yml for the workflow question; the template ships it unconditionally today).
2. The update story matters more than the copy story: a package that has the file must lose it on copier update. Check how copier treats a file the template no longer renders — it deletes it when it is not in _skip_if_exists — and prove it in the gate's update rounds, not by assumption. If copier keeps it, the Update mode of SKILL.md says the file goes (that is the second task).
3. template/tests/test_ci.py.jinja tests the workflow; it goes or shrinks to whatever still holds (the gate line in AGENTS.md, the .copier-answers.yml tag).
4. scripts/check_template.sh: the rendered-tree assertions list the files a package must have; drop .gitea from them and add an assertion that it is absent.
5. template/AGENTS.md.jinja: remove what tells a package agent about the workflow; keep the release line (tag, changelog, deploy).

## Acceptance

- Given copier copy with default answers, when the tree is read, then .gitea/ does not exist in the package [check: sh scripts/check_template.sh]
- Given a package that still has .gitea/workflows/ci.yml at the previous tag, when copier update runs, then the file is gone and nothing re-adds it [check: sh scripts/check_template.sh]

## How to test

The template gate's update rounds already render a package from the previous tag and from v1.20.10; assert .gitea/ is absent after each round, and keep one round that starts from a tree where it exists.
