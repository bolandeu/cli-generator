What packages receive from cli-generator (the template, the gate's code and messages, the skill and the Standard) must not point at cli-generator's own development: packages are products with their own docs and decision records. Today the template's comments, docstrings and README still cite reference files that no longer exist (architecture.md, conventions.md, help-standard.md), numbered sections of the Standard ("standard §8", "§10", "§12", "§13", "the §8 shape") although the Standard has named sections only, and the plugin's own README. A gate message says "(standard §12)". SKILL.md keeps a dated history note "(Human, 2026-10-18)".

Replace each such reference: say the rule in plain words, or name the Standard's section by its name ("the Standard, Health"); drop references that add nothing. Keep the settings key `[tool.cli-generator]` (it is a real setting the gate reads, not documentation). Keep mentions of the package's own changelog. No behaviour changes: only comments, docstrings, help text, README text and messages.

## Acceptance
