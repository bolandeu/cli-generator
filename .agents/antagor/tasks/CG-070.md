The generated test of Antagor's config still asserts Antagor's own rules: the config schema number and the prefix pattern. Antagor owns both (`antagor new --prefix` sets and checks the prefix), and a change of either breaks every package's tests, as the prefix rule did before.

1. The test asserts only the package's facts it already checks (the docstring check, the gate, `heavy`, the publish keys, the deploy script). The schema and prefix assertions go.

## Acceptance

- Given a package whose Antagor config has schema 2 and the prefix ABCDEFGHIJKL, When its tests run, Then they pass [check: template/tests/test_scripts.py]

## How to test

Unit level: the template gate script renders a package and runs its suite; a case rewrites the config's schema and prefix and runs the config test.

## Basis

Follow the other assertions of the same test, which already check only the package's facts.
