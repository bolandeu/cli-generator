On Python 3.14, coverage's default core is `sysmon`. Typer evaluates the string annotations of every command on each `get_command`, which compiles new code objects, and sysmon keeps a record per code object that it never frees. A package's test suite under coverage grows with every CliRunner invoke: yandex-direct (220 commands) reached 3.5 GB and was killed by the CI runner's 3500 MB limit, while without coverage it stays at ~110 MB. Coverage's `ctrace` core does not keep these records: with it the same suite peaks at 159 MB. Every generated package gets that setting, with a one-line comment why.

## Acceptance

- Given a package generated from the template (minimal and all parts), When its pyproject is read, Then `[tool.coverage.run]` has `core = "ctrace"` with a comment naming the reason (sysmon on 3.14 keeps a record per recompiled code object) [check: sh scripts/check_template.sh]
- Given the template gate's update rounds, When `copier update` runs from the previous release tag, Then the line merges without a conflict, and the generated packages' tests and coverage gate pass [check: sh scripts/check_template.sh]

## How to test

Level: integration. Seam: the template gate renders packages and runs their pytest with coverage. Data: the existing variants and update rounds.

## Read first

- `scripts/check_template.sh` — the template gate (run, not changed)

## Out of scope

- Other coverage settings and the coverage threshold
- Packages already released (they take it on their next update)
