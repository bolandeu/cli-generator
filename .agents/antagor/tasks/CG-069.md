The template ships files that Antagor owns and keeps current, and the package's tests pin Antagor's settings. Each Antagor change broke packages (the ignore lines, the prefix rule, the checks of mode fast). Antagor now sets up every project in one command, safe to repeat: `antagor new` writes the missing layout files (agents file, CLAUDE.md, context, coding standards, the ADR format), its ignore lines, the git hooks, the Plane project and the Architect's settings, and keeps a config that already exists. `antagor upgrade --apply` brings an existing project to Antagor's current files. So the template keeps only the package's own facts and leaves Antagor's files to Antagor.

1. The template no longer ships its CLAUDE.md (`template/CLAUDE.md.jinja`), the ADR format file (`template/docs/adr/README.md`) or Antagor's ignore file (`template/.agents/antagor/.gitignore`). All three are in copier's exclude list, so `copier update` never changes or removes them in a package that has them.
2. The template keeps the files with package facts: the agents file (Standard link, gate command), the context file, the coding standards and Antagor's config with only the package's keys.
3. The root ignore file of the template holds `.DS_Store` and `Thumbs.db`, the root lines Antagor adds, so Antagor's setup does not edit a template file.
4. The package's tests assert only the package's facts: the docstring check among the checks; the gate among the checks or the remote gate with its status URL; `rb-release check` in `heavy`; the publish keys the template writes (versioning, changelog, deploy command); the agents file names the Standard and the gate. No test asserts Antagor's files, its prefix rule, its layout or keys Antagor writes (mode, worker, review, daemon).
5. The template gate script no longer needs Antagor: it drops Antagor's layout check and its check that Antagor is installed, and the template repo's CI no longer installs Antagor. Its update rounds give the package Antagor's files the way Antagor writes them (the ignore file with `state/`, `receipts/`, `scratch/`) and check they survive the update.
6. The skill's Publish: after `git init`, the first commit and `git remote add origin`, and before the tag and the first push, run `ANTAGOR_ROLE=architect antagor new --prefix <PREFIX>` (with origin set and that role, `new` runs no repository script and asks nothing), then give the Human the steps it lists. It replaces `antagor hooks install`. The existing-package reference: a package with Antagor's config runs `antagor -C <package> upgrade --apply` (replacing `antagor hooks install`); a package without it runs `antagor new` as in Publish.

## Acceptance

- Given a new package rendered from the template, When its files are listed and its tests run, Then it has the agents file, the context file, the coding standards and Antagor's config, has no CLAUDE.md, no ADR format file and no Antagor ignore file, its root ignore file holds .DS_Store and Thumbs.db, and the tests pass [check: sh scripts/check_template.sh]
- Given a package made from the previous release tag with CLAUDE.md, the ADR format file and Antagor's ignore file holding state/, receipts/ and scratch/, When copier update runs to this tree, Then the three files are unchanged and no conflict appears [check: sh scripts/check_template.sh]
- Given a package whose Antagor config also has Antagor's own lines (mode, worker, a changed review section, fast-mode checks without the gate command, the remote gate), When its whole test suite runs, Then it passes [check: sh scripts/check_template.sh]
- Given a machine without antagor in PATH, When the template gate script runs, Then it passes [check: sh scripts/check_template.sh]
- Given the skill, When the plugin is validated, Then it passes and Publish runs antagor new with the Architect role after origin is set and before the first push [check: claude plugin validate . --strict]

## How to test

The template gate script: render the variants, run each package's whole suite, update from the previous release tag and from the old tag after writing Antagor's files the way Antagor writes them, and run once with antagor removed from PATH.

## Basis

Antagor's own setup: antagor new (layout files only when missing, ignore lines, hooks, keeps an existing config; with ANTAGOR_ROLE=architect and origin set it asks nothing and runs no repository script) and antagor upgrade --apply. Follow the exclude approach the template already uses for its Antagor ignore file history and the config test that asserts only the package's keys.
