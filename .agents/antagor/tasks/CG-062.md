Two defects before the stable release.

1. `doctor` calls the network. Its `credential` check now runs the `auth status` rule with the live check on: one read-only API call per provider, 10 s timeout each. On homeserver a Windmill worker runs `doctor` often, so every run spends API quota and can fail on a network blip. `doctor` must stay offline: its `credential` check uses the same rule without the live check (presence only: a required provider that is missing fails; present is `unchecked`, which is ok). The live proof stays with `auth status --check`.
2. The package CI does not run on the remote gate's branch. The template's CI workflow runs on a push to `main` and tags only, so a package with the remote publish gate gets no CI run on its candidate branch `antagor/publish-<commit>` and its publish stops. The workflow also runs on a push to `antagor/publish-*`.

## Acceptance

- Given a package with auth whose provider makes a network call in its health check, When `doctor --json` runs, Then no provider health call is made, and `credential` is ok when every required provider has a credential (status `unchecked`) [check: sh scripts/check_template.sh]
- Given a required provider with no credential, When `doctor --json` runs, Then `credential` is ok=false and `healthy` is false [check: sh scripts/check_template.sh]
- Given a package rendered from the template, When its CI workflow is read, Then a push to `main`, to a `v*` tag and to `antagor/publish-*` branches each trigger it [check: sh scripts/check_template.sh]

## How to test

Unit tests in the template's auth tests through the CLI runner: a demo provider whose health call fails the test if made. The CI trigger: the template's own CI test reads the workflow YAML. The template gate renders the variants and runs them.

## Basis

Keep the reuse of the health module's status function (only its check flag changes); keep the check names and the `--json` shape. In the workflow add the branch next to `main`, nothing else.
