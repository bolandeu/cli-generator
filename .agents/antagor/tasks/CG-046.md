Since v1.21.0 a package runs the gate as `uvx --from "git+https://homeserver.tailee01ab.ts.net:3000/bolandeu/cli-generator.git@<template tag>#subdirectory=gate" rb-release check`; the library rb-cli-core, the copier question adopt_core and the copied scripts/release.py are gone (ADR 0013). The skill and the repo README still tell an agent to pass `--data adopt_core=true`, to run `uv run scripts/release.py --check` or `uv run rb-release check`, and give an Update step "Switching the gate to rb-cli-core". An agent that follows them today breaks a package.

Make every place that names the gate give the uvx command at the template tag. Replace the Update step about rb-cli-core with one step "Switching to the gate through uvx" for a package on an older template (a copied scripts/release.py, or rb-cli-core in its dev group): clean tree; `uvx copier update --trust --defaults` (or the staged script for a worker that may not commit); check scripts/release.py and rb-cli-core are gone from tracked files, and the gate line in the package's Antagor config (its checks) is the uvx command (the update may keep an old line there; the readme is not updated by copier); `uv lock`; refresh help snapshots; run the gate until it ends with "release: gate passed"; release. Older Update steps keep their history but end with the current gate command. The full rewrite of the skill into two modes is the next epic: change only what names the gate.
