A project generated with adopt_core=true takes the shared output layer from rb-cli-core 0.2 (CORE E-002) instead of carrying its copy. The output layer, the errors module and the version module stay where commands import them from, as thin modules: each re-exports the shared part from the core, and the package's own additions live next to it (its own CliError subclasses in the errors module, its own human rendering in the human output module). The generated entry point hands the package's identity (distribution name) to the core once at start. rb-cli-core>=0.2,<0.3 moves from the dev group to runtime dependencies, from the explicit gitea index. A project with adopt_core=false renders exactly as in template v1.20.9. The standard (architecture.md) says the same, in the same commit.

## Acceptance

- Given a project rendered with adopt_core=true, When its files are read, Then the output, errors and version modules import the shared part from rb_cli_core and hold no copy of it, and pyproject lists rb-cli-core>=0.2,<0.3 in [project] dependencies (not dev) with the gitea index source [check: sh scripts/check_template.sh]
- Given that project, When its own tests run (help snapshots, envelope, exit codes, describe), Then they pass unchanged, and a command with cli_name sitemap-xml / package rb_sitemap_xml names sitemap-xml and rb-sitemap-xml [check: sh scripts/check_template.sh]
- Given a project rendered with adopt_core=false, When it is compared with the same answers rendered from tag v1.20.9, Then no file differs except the answers file's _commit [check: sh scripts/check_template.sh]
- Given architecture.md, When the layers and the adopt_core section are read, Then they say which modules come from the core and which stay the package's [check: sh scripts/check_template.sh]

## How to test

Integration through the template gate (copier copy into temp dirs, the generated project's own tests). Red first: extend the adopt_core=true variant's checks (no copy, runtime dependency) before the template change.

## Basis

The gate's adopt_core switch of E-004 (copier _exclude templated on adopt_core, the pyproject switch, check_core_adopted in the gate). Imports in commands do not change.
