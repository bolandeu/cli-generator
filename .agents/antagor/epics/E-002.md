## Problem

After creating a package with the cli-builder skill, getting it onto machines needs a manual step: the agent messages sysadmin, sysadmin edits tools.toml by hand. The Human wants: create the package with the skill, and it is installed everywhere by itself.

## Goal

A package made by the skill carries [tool.rb.install]; after its first tag sysadmin's tool-updater (homeserver) and Mac agent install it with no message and no tools.toml edit; the skill installs it once on the Mac right after the first tag for instant use.

## Acceptance (Given–When–Then)

- Given a project generated with default answers, When pyproject.toml is read, Then it has [tool.rb.install] with homeserver = ["rbtools"] and mac = true
- Given a project generated with install answers 'publish only', When pyproject.toml is read, Then [tool.rb.install] has homeserver = [] and mac = false
- Given a generated project whose [tool.rb.install] is missing, When release.py --check runs, Then it fails naming the missing section and how to add it
- Given [tool.rb.install] with a wrong shape (mac not a bool, homeserver not a list of user names, an unknown key), When release.py --check runs, Then it fails naming the key and the expected shape
- Given an existing generated project, When it runs copier update to the new template, Then it gets [tool.rb.install] with the default answers and its gate passes; packages still listed in sysadmin's tools.toml keep working (tools.toml wins)
- Given the cli-builder skill's Publish section, When an agent follows it for a new tool, Then it pushes to Gitea, tags v0.1.0, installs once from the Gitea registry on the Mac, and sends no message to sysadmin
- Given sysadmin has not yet confirmed that tool-updater and the Mac agent read [tool.rb.install], When the epic is ready, Then the template version that drops the sysadmin message is not released

## Implementation decisions

- Contract: architecture.md §1 'Distribution' states the [tool.rb.install] contract agreed with sysadmin (homeserver: list of users, [] = build and publish only; mac: bool; extras: optional list; section present = published on every tag; tools.toml overrides; command = first [project.scripts]); installation itself stays sysadmin's area
- Template: copier questions for the install targets (homeserver users, mac) rendered into pyproject.toml's [tool.rb.install]; ADR 0003 (optional parts are copier questions)
- Gate: release.py --check validates [tool.rb.install] presence and shape (stdlib tomllib), with an AI-readable failure
- Skill: Publish drops install-verification from the GitHub mirror, the local 'uv tool install .' and the sysadmin message; adds one 'uv tool install --index gitea=<registry>/simple <dist>' after the first tag; rename transition becomes a note that tool-updater follows the new name

## Test seams

- release.py --check in a generated project
- scripts/check_template.sh (default and publish-only install answers)

## Out of scope

- tool-updater, the Mac launchd agent and tools.toml — sysadmin's
- Windmill wiring of a tool (the Human's per-tool security decision)
- Switching dependency sources ([tool.uv.sources]) or DEPENDENCY_TOO_OLD actions to the registry
- Libraries not generated from this template (their owners add the section by the contract text)
