In human mode the output module prints an error's message and action, and a verbose progress line, as rich markup without escaping them. Rich takes text in square brackets for markup and drops it: an error "[library] path not found" or an action naming "[a-z0-9-]" reaches the user without that text. JSON mode is right.

1. The error output and the verbose line escape the message, the action and the progress text; only the template's own styling stays markup (as the human output helpers already do).
2. A test runs a command that fails with a message and an action holding square brackets, and asserts both reach stderr whole in human mode.

## Acceptance

- Given a command that fails with the message "[library] path not found" and the action "use [a-z0-9-]", When it runs in human mode, Then stderr holds both texts whole [check: template/tests/test_cli.py.jinja]
- Given verbose mode and a progress line holding square brackets, When the line is printed, Then stderr holds it whole [check: template/tests/test_cli.py.jinja]

## How to test

Unit level through the CLI runner of the generated package: a test command raising the error, stderr captured in human mode. The template gate script renders and runs the suite.

## Basis

Follow the human output helpers, which escape every piece of data they put inside markup.
