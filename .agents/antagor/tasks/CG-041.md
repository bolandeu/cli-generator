From IDEA-290 (mediagen). A package may ship extra agent skills besides its conventions skill: process skills per kind of work (mediagen: og-image, video, logo) that call the CLI and hold no logic. Today only the bundled conventions SKILL.md can ship; skills in a repo's .agents/skills/ are not in the wheel, so a package would patch the template's skill command and conflict on every copier update. Optional: a package without extra skills sees no change.

Extra skills live in the package data as skills/<name>/SKILL.md (Agent Skills format, frontmatter name <cli>-<name>). `skill install` installs the conventions skill and every extra one, each in its own directory named after its frontmatter name; `--skill <name>` installs one. `skill list` shows the bundled skills (name, description). `describe --json` lists them. `--ai` still prints only the conventions skill. A test checks every bundled skill: frontmatter present, name = <cli>-<dir name> (or <cli> for the conventions skill), and that no skill lists the CLI's commands (standard §9).

## Acceptance

- Given a generated project with no extra skills, When skill install --tool claude-code runs, Then it writes only <cli>/SKILL.md as before and the output is as in v1.20.9 [check: sh scripts/check_template.sh]
- Given extra skills og-image and video in the package data, When skill install --tool claude-code --project runs, Then .claude/skills/<cli>/SKILL.md, .claude/skills/<cli>-og-image/SKILL.md and .claude/skills/<cli>-video/SKILL.md exist, and --json lists the three paths [check: sh scripts/check_template.sh]
- Given the same project, When skill install --skill video runs, Then only <cli>-video is installed; When --skill nope runs, Then it fails with INVALID_ARGUMENTS (exit 2) naming the bundled skills [check: sh scripts/check_template.sh]
- Given the same project, When skill list (and --json) runs, Then it shows <cli>, <cli>-og-image and <cli>-video with their descriptions; describe --json has the same list [check: sh scripts/check_template.sh]
- Given an extra skill whose frontmatter name is not <cli>-<dir name>, or with no frontmatter, When the project's tests run, Then a test fails naming the file [check: sh scripts/check_template.sh]
- Given architecture.md §9 and SKILL.md, When they are read, Then they describe extra skills (where, naming, no command lists) and Update mode notes that a package with skills elsewhere moves them into the package data [check: sh scripts/check_template.sh]

## How to test

Integration through the generated project's own tests (CliRunner, tmp HOME/cwd), with a fixture package data dir holding two extra skills written by the test; the template gate runs them for every variant. Red first.

## Basis
