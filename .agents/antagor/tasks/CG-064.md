The template writes its own agents file and coding standards into each package, and part of them retells Antagor's process in old words ("ticket"/«тикет», "scenario"/«сценарий»; "the release is run only by the Human"; how publish builds the changelog). It goes stale. The Human's rule: a package works by Antagor's own, current rules. Antagor keeps its rules in its skill antagor-method, installed and updated with Antagor on every machine, and its layout skeleton (`antagor layout init`: the agents file, the glossary, the coding standards, the ADR folder). So the template keeps only what is the package's own and takes Antagor's skeleton as it is.

1. The generated agents file is Antagor's skeleton, the same pointers and the same «Architect only» section as `antagor layout init` writes today, plus the package's own lines: the Standard link and the gate command. No line describes Antagor's process.
2. The generated coding standards keep only judgement rules about this package's code and tests (thin commands, providers, secrets, test rules). Every line about Antagor's process goes (who runs a release, how the changelog is built, tickets).
3. The generated readme names no Antagor process beyond "work and releases go through Antagor".
4. The skill (SKILL.md and its reference files, the Standard included) does the same: no retelling of Antagor; where a sentence must name Antagor's unit of work it says "task"/"epic"; a "ticket to sysadmin" becomes a "request to sysadmin".
5. Generated test comments "Scenario N … approved by the user <date> (T30)" become "Case N", with no date or id.
6. Words not about Antagor stay ("scenarios that can't happen", Given–When–Then acceptance).

## Basis

Take the skeleton text from antagor's layout module (`antagor layout init` in an empty git repo prints the files) at its current main; keep its English. Generated package rules stay in Russian, the skill in English. No package rule changes its meaning. No mention of our own ADRs, plans, ticket or idea ids, or dates (the no-dev-docs test checks it). `antagor layout check` on a rendered package still reports the layout complete.
