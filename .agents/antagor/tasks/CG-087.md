Row F4.4 of the CG-082 extraction: template/src/*/core/tables.py ships items, responses and their views as examples, and a package that writes its own tables then gets the template ones merged in on copier update as duplicates.

Make the db part ship an empty tables.py (the SQLAlchemy Base and nothing else) and move any example into documentation or a test fixture. Check what the migrations, tests and doctor/describe read, so nothing breaks: x-rb-data in describe lists tables from this module, and tests/test_db.py.jinja exercises it.

If the example tables are the only thing that makes the db part runnable in a fresh package, say so in the task report instead of deleting them: then the fix is the update flow, not the file.

## Acceptance

- Given copier copy with the db part on, when the package core/tables.py is read, then it declares only what the package itself needs, with no items/responses example table [check: sh scripts/check_template.sh]
- Given a package updated from the previous tag, when the update merges tables.py, then no duplicate example table appears [check: sh scripts/check_template.sh]

## How to test

The template gate renders the all-parts package and the update rounds; assert tables.py has no example table on a fresh render and after an update round.
