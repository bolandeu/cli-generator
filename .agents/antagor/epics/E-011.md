## Problem

The project check was 'claude plugin validate . --strict'. The claude binary is not installed on this machine (2026-11-08), so the check was red on main, and every task that ran it blocked with environment_broken — CG-081, then CG-080. The Architect cannot add the replacement script: the guard refuses a commit that adds a file under scripts/. So the check is removed until this epic ships it, and the manifest is unguarded in the meantime.

## Goal

A change to .claude-plugin/plugin.json or to the skill frontmatter is still checked by the project checks, with no external binary: a script in the repository does the part of 'claude plugin validate --strict' that applies here.

## Acceptance (Given–When–Then)

- Given .claude-plugin/plugin.json, when the project checks run, then a script in the repository validates it: JSON parses, name/description/version present, name is a slug, skills/cli-builder/SKILL.md exists with name and description in its frontmatter
- Given a broken manifest, when the checks run, then the script exits non-zero and names the missing field

## Implementation decisions

- The check is a script in this repo, not an inline shell one-liner: the same command is documented in AGENTS.md and read by a human.

## Test seams

- the script's exit code

## Out of scope

- marketplace and hook validation of Claude plugin tooling: nothing in this repo needs it
