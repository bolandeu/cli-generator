Research and draft an ADR (status: proposed) on making the Gitea PyPI registry (https://homeserver.tailee01ab.ts.net:3000/api/packages/bolandeu/pypi/simple) the primary install channel for generated CLIs instead of 'uv tool install git+https://github.com/bolandeu/<repo>.git@vX'. Answer with evidence: (1) auth — does a private registry need a token on every machine, how uv gets it (UV_INDEX_* env, keyring, netrc), how that compares to today's gh auth; (2) reach — machines/CI outside the tailnet; keep the GitHub mirror as a fallback or not; (3) publish — who uploads the wheel (deploy.sh / release.py), with which credential, idempotency on re-run; (4) consumers — what changes in [tool.uv.sources] for inter-package deps, require_cli install_url, DEPENDENCY_TOO_OLD 'action' commands, SKILL.md install line, copier update for existing projects; (5) dependency confusion — index priority (uv index strategy, explicit=true) so a registry name never resolves from PyPI. End with options, recommendation and the list of follow-up tickets. Do not change template/ or the contract text beyond a 'proposed' note.

## Basis

architecture.md §1 'Distribution' and §8 (release, require_cli install_url, DEPENDENCY_TOO_OLD actions); Gitea PyPI registry docs (https://docs.gitea.com/usage/packages/pypi).
