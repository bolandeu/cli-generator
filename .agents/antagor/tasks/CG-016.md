Every generated CLI gets a top-level command 'docs [--out FILE]' that prints one deterministic OpenCLI 0.1 document for people (rendered later by InSpectra on the Mac): opencli, info, commands, options, arguments, examples at the root (not under 'command'). Take the generic module core/docs.py from the semkit repository (the latest tag that contains SEMKIT-058; check its git log for SEMKIT-058 before you start, and block if it is not there) as one snapshot, with no semkit names; keep its Inherited hook (options only, recursive on the parent, never positional). The command module follows the describe command (output.guard, global options, error envelope). describe output stays the same except arity.maximum 1 on options that do not repeat.

## Acceptance

- Given a generated project, When '<cli> docs' runs, Then stdout is JSON with opencli, info, commands, options, arguments, examples at the root and every template command (init, status, doctor, run, describe, docs, auth, skill, config) is in commands [check: template/tests/test_docs.py.jinja]
- Given describe's docstring 'Example: {cli} describe --json', When docs runs, Then describe's examples field is ['--json'] and its description has no 'Example:' line [check: template/tests/test_docs.py.jinja]
- Given a test command whose example is followed by '-> RESULT', When docs runs, Then its examples entry is 'ARGS  # -> RESULT' [check: template/tests/test_docs.py.jinja]
- Given a test command whose Example does not start with '<cli> <command path>', When docs runs, Then exit code 1, the error names the command and the example, and nothing is written to stdout or --out [check: template/tests/test_docs.py.jinja]
- Given an option with default 10 and choices a|b, When docs runs, Then its description ends with the line 'Default: 10. Allowed: a, b.' [check: template/tests/test_docs.py.jinja]
- Given a boolean flag and a multiple option, When docs runs, Then the flag ends with 'Default: off.' and has arity maximum 1, and the multiple option has no maximum [check: template/tests/test_docs.py.jinja]
- Given docs run twice on the same code, When the outputs are compared, Then they are byte for byte the same [check: template/tests/test_docs.py.jinja]
- Given --out FILE, When docs runs, Then FILE holds the same bytes and stdout is empty [check: template/tests/test_docs.py.jinja]
- Given --out in a missing directory, When docs runs, Then the standard error envelope, a non-zero exit and no file [check: template/tests/test_docs.py.jinja]
- Given a test group with an Inherited hook naming one option and one positional argument, When docs runs, Then the option appears once on the group with recursive true and not on each subcommand, and the positional argument is not inherited [check: template/tests/test_docs.py.jinja]
- Given describe --json, When compared with its snapshot, Then the only change is arity.maximum 1 on non-repeatable options [check: template/tests/test_describe.py.jinja]

## How to test

Integration through the CLI runner (typer.testing.CliRunner) in the generated project: run docs, json.loads the output, check fields; test-only commands on a throwaway Typer app for the error, choices and hook cases. No InSpectra, no dotnet. The project gate runs it in both include_auth variants.
