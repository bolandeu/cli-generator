Write the help standard and describe the docs command in the plugin's reference, per epic E-001 and ADR 0008.
1. reference/help-standard.md: move semkit's draft (docs/help-standard.md in the semkit repository, latest tag with SEMKIT-058) as it is, neutral wording (a command, not a step). It must state: summary = first sentence, one line; description = the paragraphs after it without option lines and Example lines; option text lives in the option's help; default, allowed values and repeatability come from the signature; the exact last line 'Default: X. Allowed: a, b.' ('Default: off.' for a flag); 'Example: <full command>' optionally followed by '-> <result>'; in the OpenCLI document an example is only what follows '<cli> <command path>', as 'ARGS  # -> RESULT'; a hook inherits options only, recursive on the parent, never positional arguments; the document is byte for byte deterministic; the help test and the project's help allowlist (tests/help_allowlist.txt, never overwritten by copier update).
2. architecture.md: in AI-first output (§5) and consumer contracts (§13): describe = the machine contract (unchanged, plus arity.maximum), docs = the human document for InSpectra (Mac only, rendered by the shared clidocs tool, not by the CLI); link help-standard.md.
3. conventions.md: the global command list gains docs [--out FILE]; describe gains arity.maximum.
4. SKILL.md: Scaffold/Refactor verify mention docs; Update mode gets a crossing step for the template release with docs: run the help test, paste the printed command paths into tests/help_allowlist.txt, empty it over time by bringing docstrings to the standard.
5. README.md: one line on docs and help-standard.md in the layout list.
Keep each file's style.
