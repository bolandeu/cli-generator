cli-generator's own template gate (the script that renders the template's variants and runs their checks) runs on the Mac today and waits in the Mac's machine queue. Run it on homeserver in Gitea Actions instead: a workflow in this repo, on every push and on demand (workflow_dispatch), runs the template gate and sets the commit status. The publish step will later wait for that status (an Antagor change, out of scope here).

The job copies the layout of the template's own Gitea workflow (the CI that generated packages get): runs-on docker, container node:22-bookworm with --init, the ci-cache volume at /cache, the uv cache env vars, uv bootstrapped into /cache/bin, gitleaks and osv-scanner linked from /cache/bin onto PATH. Python 3.12 through uv. It installs the antagor CLI pinned to a tag: `uv tool install "git+https://homeserver.tailee01ab.ts.net:3000/bolandeu/antagor.git@<tag>"`, because the gate runs antagor's layout check on each generated project; take the tag from the task's Feedback, or v0.2.0 if none is given yet, and say which in the report. The plugin validation (claude plugin validate) stays a Mac-only check: not in the workflow. The job has a 1 h timeout; the runner gives it 3.5 GB and 3 CPUs.

Every `uses:` action tag in the workflow must exist (some actions publish no floating major tag).

## Acceptance

- Given this repo, When its workflow is read, Then it runs on push and on workflow_dispatch, uses the docker runner with the ci-cache volume, installs uv, gitleaks, osv-scanner and antagor at a pinned tag, and runs the template gate as its last step [check: tests/test_repo_ci.py]
- Given the workflow, When every uses: action tag is looked up, Then each exists [check: tests/test_repo_ci.py]
- Given the template gate, When it runs on the Mac, Then it still passes [check: sh scripts/check_template.sh]

## How to test

A repo test parses the workflow YAML (triggers, runner, container, cache volume, the install steps, the gate as the last step, the antagor tag pinned) and checks the action tags against a list kept in the test. The real run on homeserver is the Architect's check after the merge.

The template's Gitea workflow for the job layout and the tool installs.
