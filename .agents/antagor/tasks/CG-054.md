The first real run of the existing-package mode (a package on template v1.15.0) found gaps in the mode and the Standard. Fix them in text only.

1. Antagor path. In a project under Antagor the Architect may not commit package files and the worker does not commit. The mode says how to work there: the Architect runs the gate in a throwaway clone (with temporary fixes) until it has every red step, then writes one task that lists them; the worker fixes them test-first, and the red run of each new test is in its report, not in git history. Every Python module the worker touches needs a module docstring (Antagor refuses the task otherwise).
2. Gate tag. The gate exists only in template tags v1.21.0 and later, so `_commit` of an old package can point at a tag with no gate. In the loop the tag is the latest tag of cli-generator; `_commit` is the tag only after a copier update. A workflow or a test ported from the template without an update pins that tag as a constant instead of reading `_commit`.
3. Old gate in the loop. The loop says, as a fix, to remove the old gate (the old release script, its tests, an old gate line in the Antagor `checks`), and that removed tests are reported as removed existing tests, not as edited ones.
4. Install choice. Standard, Install says how to choose the values: `homeserver = ["rbtools"]` when an agent or an automation on homeserver runs the command; `mac = true` when the Human or an agent on the Mac runs it; a library has `[]` and `false`; when unsure, both on.
5. Gate in CI after the push. Standard, Release, a Recommended rule: `antagor publish` runs no full gate before the tag (no `gate_command` in `[publish]`); the task checks run the gate before review, and the CI workflow runs it after the push; a red CI after the tag is fixed by the next patch release.
6. The update part of the mode has a step: drop `gate_command` from `[publish]` of the Antagor config if it is there.
