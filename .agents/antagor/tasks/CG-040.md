A package agent must find in the skill how to take the output layer from the core: Update mode gets a numbered step after step 14 with exact commands, and Scaffold stays on adopt_core=true (new packages get the core's output layer from the start). The step covers the cases met in the real packages: 7 of 16 edited the shared part of their copy, 11 added their own errors, 7 their own rendering.

## Acceptance

- Given SKILL.md Update mode, When the new step is read, Then it gives the exact commands (copier update through the worker script with the new template version, uv lock, the help snapshots refresh, rb-release check) and what must hold after (no copy of the shared part, rb-cli-core>=0.2,<0.3 in dependencies, help snapshots unchanged) [check: sh scripts/check_template.sh]
- Given a package that edited the shared part of its copy, When the step is read, Then it says how to see the edit (git log on the copied modules against the template tag) and to port it to rb-cli-core through a ticket to cli-generator first; no local copy is kept [check: sh scripts/check_template.sh]
- Given a package with its own errors and rendering, When the step is read, Then it says they stay in its errors and human output modules, subclassing or calling the core, and how to resolve the conflict in those files [check: sh scripts/check_template.sh]
- Given a package already on adopt_core=true, When Renovate opens the copier-update PR for this template version, Then the step says the PR's CI stays red until the step is done by the package agent, and that it is not merged before [check: sh scripts/check_template.sh]

## Basis

Follow step 14 (the gate from rb-cli-core) in shape: numbered sub-steps, worker command, the case of a package that edited its copy.
