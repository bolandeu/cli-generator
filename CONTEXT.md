# cli-generator

Плагин Claude Code с навыком `cli-builder` и copier-шаблоном: заводит новые CLI-инструменты или переводит старые на единую архитектуру (Python + uv + Typer).

## Словарь

**Шаблон** (`template/`):
Copier-шаблон, из которого рождается сгенерированный проект. Версии шаблона — теги этого репозитория.
_Избегать_: скелет, boilerplate

**Сгенерированный проект**:
Пакет, созданный из шаблона; у него свой `AGENTS.md`, свой гейт и свой релизный процесс.
_Избегать_: клон, форк шаблона

**Навык `cli-builder`**:
Инструкция агенту (`skills/cli-builder/`): режимы Scaffold, Refactor, Update и публикация.

**Контракт формы** (`reference/architecture.md`):
Что обязан соблюдать любой сгенерированный CLI: слои, хранение, учётные данные, dry-run, дистрибуция.

**Конвенции** (`reference/conventions.md`):
Дословные JSON-конверт, коды ошибок и выхода, глобальные опции — одинаковые у всех CLI.

**Три имени**:
`package_name` (импорт, keychain, префикс env, каталог), `cli_name` (команда), `dist_name` (`[project] name`, по умолчанию `rb-<slug>`).

**Гейт**:
`scripts/release.py --check` в сгенерированном проекте: единственная локальная проверка перед релизом.
_Избегать_: CI как источник истины

**Опциональная часть**:
Часть шаблона, включаемая вопросом copier (`include_auth`, `include_providers`, `include_http_provider`, `include_db`, `include_ci`, `dist_name_legacy`), а не удалением файлов.

**Контракт потребителя**:
YAML в `tests/contracts/<потребитель>/` сгенерированного проекта (формат `contract: 1`): потребитель описывает, что ждёт от CLI; гейт прогоняет его отдельным шагом.
_Избегать_: интеграционный тест

**Владелец стандарта**:
Агент этого репозитория; владеет стандартом всех CLI-пакетов Человека (контракт, шаблон, релиз).

**Справка для человека** (`<cli> docs`):
Детерминированный OpenCLI-документ с командами в корне, который InSpectra превращает в HTML-страницу (`clidocs`). Отдельно от `describe`: тот — контракт для машин и не меняется ради справки.
_Избегать_: describe для людей, help-страница

**Стандарт справки**:
Правила docstring команды: summary — первое предложение; строки `имя: текст` — только у своей опции; `Example:` — полная команда, в документ идёт хвост после пути команды; значение по умолчанию, допустимые значения и повторяемость — из сигнатуры.
_Избегать_: формат help

**Ядро** (`rb-cli-core`, репо `bolandeu/cli-core`):
Общая библиотека стандарта: вывод, коды ошибок, учётные данные, провайдеры, `doctor`, гейт `rb-release`. Пакет зависит от неё диапазоном версий из реестра Gitea вместо копий в своём коде; новая версия стандарта доходит подъёмом версии.
_Избегать_: общий модуль, vendored core

**Переход на ядро** (`adopt_core`):
Вопрос copier: «да» — пакет берёт модуль из ядра, его копия удаляется; «нет» (по умолчанию для существующих) — копии остаются, поведение не меняется. Модули переезжают по одному.
_Избегать_: миграция всего сразу
