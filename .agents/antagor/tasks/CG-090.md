Row F5.2 of the CG-082 extraction: core/errors.py ships DatabaseUnavailable, DatabaseNotMigrated and DatabaseTooNew in every package, including the ones generated with include_db false, where nothing can raise them.

The parts already work by copier's templated _exclude and by probing a module at runtime; pick the way that fits the module (a conditional block in errors.py.jinja, or a small module the db part brings). Check what reads them: core/db.py, commands/db.py, the exit-code table in Errors and describe's exitCodes.

## Acceptance

- Given copier copy with include_db false, when the package core/errors.py is read, then it defines no DatabaseUnavailable, DatabaseNotMigrated or DatabaseTooNew [check: sh scripts/check_template.sh]
- Given copier copy with the db part on, when the errors module is read, then those three errors are there and the exit codes in describe still match [check: sh scripts/check_template.sh]

## How to test

The template gate renders the minimal package and the all-parts package; assert the three names in one and their absence in the other, and that the rendered package imports cleanly in both.
