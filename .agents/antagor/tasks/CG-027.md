release.py --check gets a secret-scan step: gitleaks over the git history; a finding fails the gate at that named step with exit 1; without gitleaks on PATH the step is skipped with a notice (like osv-scanner). The template .gitignore covers .env and .env.*. A dependency on one of our packages is declared with a version range and resolved only from the Gitea PyPI index marked explicit; the gate's guard against a same-name PyPI package now checks the explicit index source instead of a git source. The comment that names tools-watch is reworded (no such tool).

## Acceptance

- Given a generated project with a committed fake AWS key, When release.py --check runs with gitleaks on PATH, Then it stops at the secret step, prints the finding without the secret value, last line 'release: code failed', exit 1 [check: template/tests/test_scripts.py]
- Given gitleaks is not on PATH, When release.py --check runs, Then the secret step prints a skipped notice with the install command and the gate result is unchanged [check: template/tests/test_scripts.py]
- Given a generated project, When a .env and a .env.local file are created, Then git status is clean [check: template/tests/test_scripts.py]
- Given a project that depends on a package rb-x from an explicit index while PyPI has a higher rb-x, When uv lock and release.py --check run, Then rb-x comes from the explicit index and the gate passes; a dependency installed from PyPI instead fails with a named error [check: template/tests/test_scripts.py]
- Given the rendered pyproject.toml, When it is read, Then it declares the Gitea index https://homeserver.tailee01ab.ts.net:3000/api/packages/bolandeu/pypi/simple with explicit = true, and a project without such dependencies still locks offline from its cache [check: sh scripts/check_template.sh]

## How to test

Unit and integration in the generated project's test_scripts.py: run release.py steps with a temp git repo; for the index guard use a local flat or file:// index fixture under tests/data, no network. check_template.sh renders all variants.

## Basis

Follow the osv-scanner step (skip notice, StepFailed, named step) and the existing 'installed from a package index instead of their git source' guard in release.py; read uv docs on [[tool.uv.index]] explicit and sources by index (context7).
