One short English Standard replaces the three reference files. It is what a package must and should be; a package agent reads it once. Plan: docs/plans/simple-standard.md (decisions 1-9 and the lists "Обязательно" and "Необязательные части").

Shape:
- Named sections, no numbers: Technology, Commands, Output, Errors, Health, Credentials, Install, Docs, CI, Release; then Optional parts, one subsection each: Project, Credentials and providers, HTTP, Database, Package skill, Describe, Consumer contracts, Detach.
- Every rule is marked **Mandatory** or **Recommended**. Every mandatory rule names the gate step that checks it (`standard: commands`, `standard: json`, `standard: errors`, `standard: health`, `standard: docs`, `standard: ci`, and the existing steps: lint, format, types, tests, secrets, install section, build + install wheel). A rule no step checks is Recommended.
- At most one line of "why" per rule. Long reasoning, history and incident notes leave: what still matters goes into an ADR under docs/adr, the rest is dropped (git keeps it).
- Template mechanics (copier questions, file names inside the template) are not rules: they stay out of the Standard.
- Each optional part says when a package needs it, how to turn it on, and its rules when present.

The old reference files are removed; every reference to them in this repo outside template/ points to the Standard's named sections (SKILL.md, the repo README, docs/). The refactor checklist moves into the skill as it is (its rewrite is the next epic).

## Acceptance

- Given the Standard, When every rule is listed, Then each is marked Mandatory or Recommended, and each Mandatory one names a gate step from the list above [check: tests/test_standard_doc.py]
- Given the Standard, When it is searched for section numbers (§ followed by a digit), Then there are none; sections are the named ones above [check: tests/test_standard_doc.py]
- Given this repo outside template/, When it is searched for architecture.md, conventions.md and help-standard.md, Then nothing names them except git history and docs/adr [check: tests/test_standard_doc.py]
- Given the plugin, When it is validated, Then it is valid [check: claude plugin validate . --strict]

## How to test

A repo test reads standard.md (rule markings, gate step names, no § numbers) and searches this repo outside template/ for the old file names. Red first.

## Basis

The three reference files are the source: keep every rule that is still true, merge duplicates, drop history. Plan docs/plans/simple-standard.md for what is mandatory and what is optional.
