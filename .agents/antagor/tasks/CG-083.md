The claude binary left this machine (2026-11-08), so `claude plugin validate . --strict` — a project check until today — was red on main and blocked every task with environment_broken (CG-081, CG-080).

Add `scripts/check_plugin.py`: the part of that validator that applies here, nothing more. Behaviour:

1. Read `.claude-plugin/plugin.json`; a parse error is a failure.
2. Require the keys `name`, `description`, `version`.
3. `name` matches `[a-z0-9]+(-[a-z0-9]+)*`.
4. `skills/cli-builder/SKILL.md` exists, starts with `---\n`, and its frontmatter has a non-empty `name` and `description`.
5. Print one line on success (`plugin: <name> v<version>, skill cli-builder ok`); print `<what is wrong>` to stderr and exit 1 on any failure.
6. No dependencies outside the standard library; it must run under `python3` on the gate's Python and on the machine's.

Then wire it in: `.agents/antagor/antagor.toml` `checks` gets `python3 scripts/check_plugin.py` next to `sh scripts/check_template.sh`, and `AGENTS.md` already tells a human to run it.

Prove both ends: the current manifest passes, and a copy with a missing `version` or a non-slug name fails. Both runs go into the task report.

## Out of scope

- manifest rules this repo does not use (marketplace, hooks)

- the rest of `claude plugin validate --strict`: marketplace rules, hook and command schemas — nothing in this repo needs them
- touching `.claude-plugin/plugin.json` itself
