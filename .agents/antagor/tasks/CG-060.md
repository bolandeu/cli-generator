The gate (rb-release) requires Python >=3.14 since the last Python change. A package's CI runs the gate on the package's lowest Python (UV_PYTHON from its requires-python), so every package still on ">=3.11" (dataio, semkit) fails before the first step: "the current Python version (3.11.14) does not satisfy Python>=3.14". The gate is a tool: it must not force the package's Python. Moving a package to 3.14 is the package's own step, later.

The gate goes back to requires-python ">=3.11" and its lock is refreshed for it. Its code stays valid for 3.11 (no syntax or stdlib API newer than 3.11). The template's packages stay on ">=3.14"; the Standard's line about 3.14 stays.

## Acceptance

- Given the gate of this working tree, When it is run through uvx on Python 3.11 (`uvx --python 3.11 --from <gate dir> rb-release check` over a rendered package), Then it installs and runs its steps, and the run ends as it does on 3.14 [check: sh scripts/check_template.sh]
- Given the gate's own sources, When ruff and ty check them with the 3.11 target taken from requires-python, Then both pass, and the gate's tests pass [check: sh scripts/check_template.sh]

## How to test

The template gate script gets one more run of the gate through uvx with Python 3.11 over the minimal rendered package (next to the existing run); the gate's ruff/ty/pytest steps of the script already use the gate's requires-python as target. Python 3.11 is installed by uv when missing.

## Basis

Only the gate's requires-python, its lock, and code that fails under the 3.11 target change. Keep the existing gate run of the script as it is; add the 3.11 run next to it, the same way.
