## Problem

Every package carries its own copy of scripts/release.py. It changes more often than any other shared file (CG-024, CG-027), and each change means a copier update with possible conflicts in every package.

## Goal

A package that answers adopt_core=yes runs the gate as 'uv run rb-release check' from rb-cli-core (Gitea registry, version range >=0.1.2,<0.2); its copy of scripts/release.py is gone; CI, antagor.toml and the project docs call the command; the gate output and exit codes are the same as before. A package that answers no is untouched. The skill tells a package agent each step; new packages start with yes.

## Acceptance (Given–When–Then)

- Given a project rendered with adopt_core=false, When it is compared with the same project from the previous template release, Then nothing changes (scripts/release.py present, CI and antagor.toml call it)
- Given a project rendered with adopt_core=true, When its files are listed, Then scripts/release.py is absent, pyproject depends on rb-cli-core>=0.1.2,<0.2 from the explicit gitea index, and CI, antagor.toml and AGENTS.md call uv run rb-release check
- Given that project, When uv run rb-release check runs, Then the gate passes with the same step names, last line and exit code as scripts/release.py --check
- Given an existing package on adopt_core=false, When copier update --data adopt_core=true runs, Then scripts/release.py is removed and the gate passes through rb-release check
- Given rb-cli-core is not reachable on the registry, When uv sync runs in an adopt_core=true project, Then it fails with uv's resolution error naming rb-cli-core, and no PyPI package of that name is installed
- Given SKILL.md, When Scaffold and Update modes are read, Then Scaffold passes adopt_core=true and Update has a numbered step for the switch with the exact commands

## Implementation decisions

- copier question adopt_core (bool, default false); templated _exclude drops scripts/release.py when true; a _migrations entry removes it on update when the answer turns true
- pyproject template: rb-cli-core>=X.Y,<next-major from the gitea index when adopt_core
- CI workflow, antagor.toml checks and AGENTS.md: the gate command depends on adopt_core
- The library side (rb-release in bolandeu/cli-core) is the CORE project's epic; this epic consumes its first release

## Test seams

- sh scripts/check_template.sh (both adopt_core variants + update round)
- uv run rb-release --check output and exit code in a generated project

## Out of scope

- Moving output, credentials, providers, doctor (later epics, docs/plans/cli-core.md)
- Removing the copies from the template (last epic, after all packages moved)
- copier update in real packages (their agents, on the Human's command; semkit first)
