SKILL.md becomes the order of the agent's actions and the choice of mode, nothing more: a new package goes to the new-package mode file, an existing CLI or package goes to the existing-package mode file (written by a sibling task; SKILL.md only names it). The parts both modes share stay in SKILL.md, short: Publish and the non-negotiables. The new-package mode: copier copy with the minimal defaults; turn on only the optional parts the package needs, each by its copier question (include_project, include_auth with include_providers and include_http_provider, include_db, include_skill, include_describe, include_contracts), with one line on when each is needed, pointing to the Standard's Optional parts; then write the package's own commands; the gate (the uvx rb-release check command at the template tag) is green before every commit. The Scaffold, Refactor, refactor checklist and Update sections leave SKILL.md: the new-package mode takes what Scaffold still needs; the rest moves to the existing-package mode file in the sibling task, so this task just removes it. Keep the skill's frontmatter and its trigger description valid.

- Given the new-package mode, When an agent follows it, Then it runs copier copy with the minimal defaults, turns on only the needed parts by their copier questions, and runs the uvx gate at the template tag before each commit [check: tests/test_skill_new.py]
