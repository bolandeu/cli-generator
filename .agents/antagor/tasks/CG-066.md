CG-065 left two defects. (1) The template no longer writes Antagor's ignore file, but Antagor writes it only in `antagor init` (which refuses a package that already has its config) and `antagor upgrade --apply`: a new package has nothing that keeps `state/`, `receipts/` and `scratch/` out of git. (2) The prefix question accepts `[A-Z][A-Z0-9]{1,11}`, but Antagor accepts only `[A-Z][A-Z0-9]{1,9}` (at most 10 characters): an 11- or 12-character answer gives a package Antagor refuses. (3) The generated test of the Antagor config pins `checks` exactly and forbids `worker`, and still pins the 12-character prefix: a package cannot follow Antagor's advice for its mode (for `fast`: `uv run pytest -q --no-cov {test_paths}` in `checks`, the full gate only through `[publish] gate = "remote"` and `heavy`) or keep its own worker, without a red gate.

1. The template writes Antagor's ignore file once, with the lines Antagor writes today: `state/`, `receipts/`, `scratch/`. It is in copier's skip-if-exists list, not in the exclude list: `copier update` never changes or removes a package's file, whatever lines Antagor has added to it.
2. The prefix validator and its help take a capital letter, then 1-9 capitals or digits (at most 10 characters), as Antagor does.
3. No test inside the generated package asserts the ignore file's lines (Antagor adds lines; such a test broke packages before).
4. The template still renders the same Antagor config. Its generated test asserts only what the template guarantees: the docstring check is among `checks`; the gate runs somewhere (the gate command is among `checks`, or `[publish] gate = "remote"` with the status URL); `heavy` holds `rb-release check`; the prefix follows Antagor's rule. A package may add or reorder checks and set `worker`.

## Acceptance

- Given a new package rendered from the template, When its files are listed, Then the Antagor ignore file is there with exactly state/, receipts/ and scratch/ [check: sh scripts/check_template.sh]
- Given a package made from the previous release tag whose Antagor ignore file holds state/, receipts/ and scratch/, When copier update runs to this tree, Then the file is unchanged and no conflict appears [check: sh scripts/check_template.sh]
- Given the answer antagor_prefix=MEDIAGEN or ABCDEFGHIJ, When the template is rendered, Then it passes and the Antagor config has that prefix; ABCDEFGHIJK, mg or 1AB is refused [check: sh scripts/check_template.sh]
- Given a package rendered from the template whose Antagor config has `checks = ["uv run pytest -q --no-cov {test_paths}", "python3 scripts/check_command_docstrings.py"]`, `heavy = ["rb-release check"]`, `worker = "claude-code"` and the remote gate, When its tests run, Then they pass [check: sh scripts/check_template.sh]

## How to test

The template gate script: the variant step checks the rendered ignore file, the update round keeps a file with Antagor's lines, the prefix loop renders the accepted prefixes and expects copier to refuse the others; one variant rewrites the rendered Antagor config the way a fast-mode package does and runs the suite.

## Basis

Follow copier's skip-if-exists list (README.md is there for the same reason) and the prefix checks CG-065 added to the template gate script. Antagor's own rule: prefix ^[A-Z][A-Z0-9]{1,9}$, ignore lines state/ receipts/ scratch/.
