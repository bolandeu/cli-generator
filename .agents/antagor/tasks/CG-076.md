The Human decided (2026-10-23) that a project's name in the Antagor config is always its folder name, never the CLI command name. The template writes the command name, so google-search-console became "gsc" and yandex-direct "yd", and Plane and the Antagor registry show the wrong project. A package's folder name is also its Gitea repository name (google-search-console, yandex-direct, serp).

Known facts, checked on a throwaway copier template: during `copier update`, `_copier_conf.dst_path` is a temporary directory (`copier._main.new_copy.<random>`), or `.` when `copier update` runs without a destination argument. It is a PurePosixPath, so `.resolve()` does not exist. A name taken from it at update time is wrong. A question's answer is kept in `.copier-answers.yml` and comes back on every update.

## Acceptance

- Given `copier copy` with `repository_url=https://homeserver.tailee01ab.ts.net:3000/bolandeu/google-search-console` and `cli_name=gsc`, When the package is generated, Then the Antagor config has `name = "google-search-console"` [check: sh scripts/check_template.sh]
- Given `copier copy` with a blank `repository_url` into a destination folder named `demo-folder`, When the package is generated, Then the name is `demo-folder` [check: sh scripts/check_template.sh]
- Given a package generated before this change whose answers have a `repository_url` ending in its repository name (with or without `.git`), When `copier update` runs, with or without a destination argument, Then the name becomes that repository name, and a package that already has it gets no conflict on that line [check: sh scripts/check_template.sh]
- Given a package with a blank `repository_url`, When `copier update` runs, with or without a destination argument, Then the name is never a temporary directory name or `.`: the package keeps the name it has, or gets one answer kept in its answers file [check: sh scripts/check_template.sh]
- Given the update instructions, When a package's name differs from its folder, Then they say how to set it once (the answer to pass, or the line to keep on conflict) [check: sh scripts/check_template.sh]

## How to test

Level: integration. Seam: copier copy/update in the template gate. Data: the existing variants, plus one with `cli_name` different from the repository name, plus an update round from the previous release tag, run with and without a destination argument.

## Basis

Follow how the Antagor config already derives the repository name for `gate_status_url` from `repository_url`. Add a question only if an answer has to be kept (the `updating` pattern for questions added after the first release, ADR 0014).

## Read first

- `template/.agents/antagor/antagor.toml.jinja` — the name line and gate_status_url
- `copier.yml` — repository_url, updating, the answers kept on update
- `scripts/check_template.sh` — the variants and the update rounds

## Out of scope

- Renaming existing Plane projects or registry entries (Antagor's)
- The prefix and every other line of the Antagor config
