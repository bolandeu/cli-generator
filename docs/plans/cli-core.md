# План: ядро `rb-cli-core`

Источник: IDEA-254, решения Человека 2026-10-19 (ADR 0010). Условие Человека: улучшать, не ломать — поведение пакетов не меняется, переход по одному пакету, неперешедшие работают как раньше. Шаги перехода и обновления — в режимах Refactor/Update скилла `cli-builder`, для агентов пакетов.

## Решения

1. Репо `bolandeu/cli-core`, пакет `rb-cli-core`, ведёт `cli-generator`. Публикация — тегом через tool-updater в реестр Gitea (`[tool.rb.install]` `homeserver = []`, `mac = false`).
2. Гейт — команда `rb-release` внутри ядра (`uv run rb-release --check`); выносится первым.
3. Переход — вопрос copier `adopt_core`, по умолчанию «нет»; новые пакеты скилл создаёт с «да».
4. Доказательство «не сломалось»: у перешедшего пакета без изменений help-снимки, тесты конверта, кодов ошибок и выхода, контракты потребителей; гейт зелёный. В ядре — те же контрактные тесты. Обновление ядра в пакетах — PR Renovate, каждый проверяет CI пакета.

## Эпики (рабочие названия, по порядку)

Порядок (Человек, 2026-10-19, по рекомендации): первым — гейт, не вывод. Гейт не участвует в работе команд (пользователь
разницы не видит), а `release.py` меняется чаще всех общих файлов; первый эпик проверяет всю цепочку (репо, реестр,
`adopt_core`, PR Renovate) там, где ошибка не задевает пользователей.

1. **Ядро и гейт.** Репо `cli-core` (отдельный проект Antagor) с командой `rb-release` (= `scripts/release.py`),
   её тестами и первым тегом. Шаблон: `adopt_core`, при «да» гейт — `uv run rb-release --check` из ядра, копия
   `scripts/release.py` удаляется, CI и `antagor.toml` зовут команду. Скилл: шаг перехода. Первый пакет — semkit.
2. **Вывод.** Конверт, `guard`, `group`, human/json, `core.errors`, `core.version` — в ядро.
   Решения Человека 2026-10-20 (по рекомендации; факты: из 16 пакетов на шаблоне свои ошибки дописали 11,
   свою отрисовку — 7, правки в `guard`/`group` — 7):
   - в ядро — только общая часть: конверт, `guard`, `group`, JSON-вывод, базовый `CliError` со стандартными
     ошибками и `EXIT_CODES`, `version`, `echo`/`echo_markup`. Свои ошибки (`core/errors.py`) и отрисовку
     (`output/human.py`) пакет держит у себя и наследует от ядра;
   - пакет, правивший копию общей части, переходит после переноса правки в ядро задачей; локальных копий нет
     (как шаг 14.6 для гейта);
   - один флаг `adopt_core`: «всё, что есть в ядре»; новый модуль — отдельный шаг режима Update;
   - ядро — runtime-зависимость: вывод — `rb-cli-core 0.2.0`, пакеты `>=0.2,<0.3`; каждое расширение ядра
     поднимает минорную версию.
3. **Ключи и провайдеры.** `credentials/` (manager, health, `auth status`), `providers/base`, `HttpProvider`.
4. **doctor, deps, остальное общее** (`core.deps`, `docs`/`opencli`, фикстуры тестов как pytest-плагин).
5. **Убрать копии.** Когда все пакеты на `adopt_core = true`: шаблон перестаёт генерировать копии, вопрос уходит.

Каждый эпик: обновление пакетов — по команде Человека, после проверки на semkit.
