On a server with credentials in environment variables and no OS keychain (homeserver: a Windmill worker runs `<cli> doctor`), every package from the template reports healthy=false although it works. Agents read a false failure. Three causes, all in the template:
1. `credential_store` is ok=false when there is no keychain backend. The Standard makes environment variables the production source and the keychain a dev convenience.
2. `credential` checks a provider named "default" unless a project config names one, and no package registers such a provider: a CLI whose provider is google is told to run `auth login --provider default`.
3. With the project part, `project` is ok=false when doctor runs outside a project.

The fix (the same shape a package already took):
- `credential` follows the `auth status` rule: ok when every required provider is ok or unchecked and none is invalid or expired; its detail names the providers. It reuses the health module's status and problem functions, it does not copy them. No check names a "default" provider.
- No keychain backend: `credential_store` is ok=true and its detail says credentials come from environment variables.
- No project found: `project` is ok=true and its detail says doctor runs outside a project. A project that is found but broken (`config`, `cli_compat`) still fails.
- Check names, their order and the `--json` shape do not change; `healthy` is all checks ok, as before.

## Acceptance

- Given a package with auth and a provider whose key is set only in its environment variable, and no keychain backend, When `doctor --json` runs, Then `credential_store` and `credential` are ok and `healthy` is true [check: sh scripts/check_template.sh]
- Given a required provider whose credential is invalid or expired, When `doctor --json` runs, Then `credential` is ok=false and `healthy` is false [check: sh scripts/check_template.sh]
- Given a package with the project part, When `doctor --json` runs outside any project, Then `project` is ok=true with a detail that says so, and with a broken project config `config` is ok=false [check: sh scripts/check_template.sh]
- Given any provider set, When doctor reports `credential`, Then no output names a provider "default" that the package does not register [check: sh scripts/check_template.sh]

## How to test

Unit tests in the template's auth and cli tests through the CLI runner (`doctor --json`), with a fake keychain backend absent and provider credentials from the environment, as the existing auth tests do; the template gate renders the minimal and the all-parts package and runs them.

## Basis

Reuse the health module's status/problem logic that `auth status` uses. Keep `doctor` always exit 0. The minimal package (no auth, no project) keeps passing.
