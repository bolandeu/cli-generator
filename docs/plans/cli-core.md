# План: ядро `rb-cli-core`

Источник: IDEA-254, решения Человека 2026-10-19 (ADR 0010). Условие Человека: улучшать, не ломать — поведение пакетов не меняется, переход по одному пакету, неперешедшие работают как раньше. Шаги перехода и обновления — в режимах Refactor/Update скилла `cli-builder`, для агентов пакетов.

## Решения

1. Репо `bolandeu/cli-core`, пакет `rb-cli-core`, ведёт `cli-generator`. Публикация — тегом через tool-updater в реестр Gitea (`[tool.rb.install]` `homeserver = []`, `mac = false`).
2. Гейт — команда `rb-release` внутри ядра (`uv run rb-release --check`).
3. Переход — вопрос copier `adopt_core`, по умолчанию «нет»; новые пакеты скилл создаёт с «да».
4. Доказательство «не сломалось»: у перешедшего пакета без изменений help-снимки, тесты конверта, кодов ошибок и выхода, контракты потребителей; гейт зелёный. В ядре — те же контрактные тесты. Обновление ядра в пакетах — PR Renovate, каждый проверяет CI пакета.

## Эпики (рабочие названия, по порядку)

1. **Ядро и вывод.** Репо `cli-core` с выводом (конверт, `guard`, `group`, human/json), `core.errors`, `core.version`; контрактные тесты; первый тег. Шаблон: `adopt_core`, при «да» вывод из ядра, копии удаляются. Скилл: шаг перехода. Первый пакет — semkit (заявка его агенту).
2. **Ключи и провайдеры.** `credentials/` (manager, health, `auth status`), `providers/base`, `HttpProvider` — в ядро.
3. **doctor, deps, version, остальное общее** (`core.deps`, `docs`/`opencli`, фикстуры тестов как pytest-плагин).
4. **Гейт `rb-release`.** `scripts/release.py` → команда ядра; шаблон и CI вызывают её.
5. **Убрать копии.** Когда все пакеты на `adopt_core = true`: шаблон перестаёт генерировать копии, вопрос уходит.

Каждый эпик: обновление пакетов — по команде Человека, после проверки на semkit.
