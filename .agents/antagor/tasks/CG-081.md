From CG-IDEA-003, the mcp architect.

Nothing in the Standard says what makes a package a member of the family. A consumer filters by the entrypoint prefix, and loses three packages that are family members:

  rb-llmkit v0.14.11               binary llm      -> describe ok, 34 commands, template v1.5.6
  rb-wordpress-bulk-editor v5.1.2  binary wp-bulk  -> describe ok, 20 commands
  rb-mediagen v0.9.0               binary mediagen -> describe ok, 26 commands

The distribution name is the identifier (Technology already says the distribution is `rb-<slug>`); the command name is a separate thing (`cli_name`) and may differ from it. `x-rb-tool` carries all three: `tool` (the command name), `dist`, `package`.

Add to the Standard, Technology, next to the three names: family membership is the DISTRIBUTION name `rb-*`; a tool is addressed by its own name, `x-rb-tool.tool`, in a document and by its command on a shell; nothing derives the one from the other, and a package whose command differs from its slug is legal.

One line in the template AGENTS.md next to the three names the same way, so a package agent does not "fix" a differing command name.

## Out of scope

- a gate step: the gate cannot tell a renamed command from a required one, and the Recommended rule already allows a documented deviation
