Generated projects fail their tests in Gitea Actions (act_runner, Linux container), found by reproducing it in Docker:
1. The runner sets GITHUB_ACTIONS=true. Typer's rich_utils reads GITHUB_ACTIONS / FORCE_COLOR / PY_COLORS once at import and forces terminal output (FORCE_TERMINAL = True), so every help snapshot differs. The help and describe snapshot tests must render the same text whatever those variables are. The fix belongs in the tests (the CLI's own output in CI is not the problem); remember the value is read at import time, so an env passed to CliRunner.invoke is too late.
2. In the job container PID 1 is 'tail -f /dev/null', which never reaps orphans. A killed detached run stays a zombie; detach's liveness check (os.kill(pid, 0)) treats a zombie as alive, so runs_status says 'running' forever and test_killed_outright fails. A zombie must count as not alive (Linux: state Z in /proc/<pid>/stat; macOS: ps -o stat=), with no new dependency.

## Acceptance

- Given GITHUB_ACTIONS=true, FORCE_COLOR=1 and PY_COLORS=1 in the environment of the test run, When the help snapshot tests run, Then they pass against the snapshots rendered without them [check: template/tests/test_help.py.jinja]
- Given GITHUB_ACTIONS=true, FORCE_COLOR=1 and PY_COLORS=1, When the describe snapshot test runs, Then it passes [check: template/tests/test_describe.py.jinja]
- Given a child process that has exited but was not reaped by its parent (a zombie), When detach checks whether its pid is alive, Then it is not alive [check: template/tests/test_detach.py]
- Given a detached run killed with SIGKILL whose supervisor is never reaped, When runs_status reads it, Then its state is killed, not running [check: template/tests/test_detach.py]
- Given a live process, When detach checks its pid, Then it is alive (no regression) [check: template/tests/test_detach.py]

## How to test

Unit/integration in the generated project on macOS (the gate): set the three variables for the test session (e.g. a subprocess pytest run with that env, or monkeypatching what typer computed at import) for the snapshot cases; create a real zombie in-test (fork/spawn a child that exits, do not wait on it) for the liveness cases. The project gate runs both include_auth variants.

## Basis

typer.rich_utils FORCE_TERMINAL logic (read at import; _TYPER_FORCE_DISABLE_TERMINAL also exists); detach._alive; the existing test_detach helpers.
