## Problem

A fresh `uv tool install` of 12 of the 19 tools on the Mac (checked 2026-11-12) dies at import with
`TypeError: TyperOption.__init__() missing 1 required keyword-only argument: "type_descriptor"`,
resolving typer 0.29.1. Both halves are in the template:

1. Generated code constructs the internal `typer.core.TyperOption(param_decls=[...])` in
   `commands/project.py` (`--project`) and `commands/skill.py` (`--ai`), appended to
   `output.RootGroup.part_options`. typer 0.29 changed that constructor.
2. `template/pyproject.toml.jinja` carries only `typer>=0.12`: any new minor lands in the next install.

A cap alone does not fix the class: the code must stop touching typer internals, and a gate step must
catch the next dependency bump instead of a fresh host finding it months later.

## Validated design (do not redesign; it was run on typer 0.27.3, 0.28.0 and 0.29.1)

A part no longer builds a click parameter. It declares its global options in a function signature and
registers the function:

```python
# commands/project.py
def _global_options(
    project: str | None = typer.Option(
        None, "--project", metavar="TEXT", help="Path to the project root.",
        expose_value=False, callback=_remember_project,
    ),
) -> None:
    """The global options this part adds to the CLI's root (declaration only: `RootGroup` reads the signature)."""
...
    output.RootGroup.part_options.append(_global_options)
```

`output.RootGroup` turns each declaration into the parameters a `TyperGroup` takes through public API —
Typer itself builds parameters from a callback signature, so the declaration is mounted on a throwaway
app and the root parameters are read back:

```python
from typer.main import get_command

def _root_params(decl: Callable[[], None]) -> list:
    spec = typer.Typer(add_completion=False)
    spec.callback()(decl)
    return list(get_command(spec).params)

class RootGroup(TyperGroup):
    part_options: ClassVar[list[Callable[[], None]]] = []

    def __init__(self, *, params=None, **kwargs):
        part_params = [param for decl in self.part_options for param in _root_params(decl)]
        super().__init__(params=[*(params or []), *part_params], **kwargs)
```

`typer.core.TyperGroup` stays: `cls=` accepting a `TyperGroup` subclass is documented public surface.
`--ai` keeps `is_flag=True, is_eager=True, expose_value=False, callback=_print_skill`.

With this, a generated package's runtime works on typer 0.29.1 too (checked: `--version`, `--help`,
`--project … status --json`, `--ai`).

## Cap

`template/pyproject.toml.jinja`: `"typer>=0.27,<0.29"`. The whole generated suite is green on 0.27.3
and 0.28.0 (checked). 0.29 is blocked by the template's own tests, not by the runtime:
`tests/test_help.py.jinja` calls `param.type_cast_value(ctx, value)` and `param.get_error_hint(ctx)`,
which typer 0.29's bundled click changed. Say that in the ADR and in the AGENTS.md sharp edge.

## Gate: the fresh-install step

Add a step to `gate/rb_release/gate.py` that does what a new host does tomorrow: install the package
into an empty environment, letting uv resolve its dependencies from the index (the existing wheel step
deliberately installs the locked set and never resolves, which is why it stayed green while every fresh
install broke). Use `uv tool install .` with `UV_TOOL_DIR` and `UV_TOOL_BIN_DIR` pointed inside the
gate's scratch dir, so the user's own tool dir is untouched and `[tool.uv.sources]` still applies; then
`<cmd> --version` must print the version being released and `<cmd> --help` must exit 0 (a library: every
top-level package imports and importlib.metadata reports the version, as the wheel step does). Name it
`fresh install`, give it `needs=WHEEL_STEP`, and list it in the module docstring's step order.

Cover it with a gate test that shows the point: a package whose dependency's next minor release removes a
name the CLI imports must fail this step while the locked wheel step stays green. Two locally built
wheels of a fake dependency (1.0 keeps the name, 2.0 drops it) plus a `[tool.uv.sources]` path/registry
source keep the test off the network — check whether `uv tool install .` honours a path source before
relying on it, and if it does not, use whatever seam keeps the test honest and local; state it in the test.
