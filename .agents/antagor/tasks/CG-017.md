The help contract test checks the help standard on every command of the registry (a new command is covered automatically): a one-line summary (the first sentence of the docstring), at least one Example line, every parameter has help, no parameter help text repeated in the docstring description, every Example parses against the command tree (path exists, options known, arguments parse; nothing is run). It uses the docstring split of core/docs (CG-016), not a second parser. Commands not yet brought to the standard are listed in a project file, the help allowlist, one command path per line, comments with #; copier update never overwrites it (copier _skip_if_exists). On failure the test prints the failing commands as ready lines for the allowlist. Bring every template command docstring to the standard, so the allowlist of a new project is empty.

## Acceptance

- Given a freshly generated project (both include_auth variants and include_db), When pytest runs, Then the help standard test passes with an empty help allowlist [check: template/tests/test_help.py.jinja]
- Given a test command whose docstring has no Example line, When the help test runs, Then it fails naming the command and the rule 'no Example' [check: template/tests/test_help.py.jinja]
- Given a test command whose summary spans two lines, When the help test runs, Then it fails naming the command and the rule 'summary not one line' [check: template/tests/test_help.py.jinja]
- Given a test command whose description repeats an option help text, When the help test runs, Then it fails naming the command and the option [check: template/tests/test_help.py.jinja]
- Given a test command whose Example uses an unknown option --nope, When the help test runs, Then it fails naming the command and the example [check: template/tests/test_help.py.jinja]
- Given failing commands listed in the help allowlist, When the help test runs, Then it passes [check: template/tests/test_help.py.jinja]
- Given a command in the help allowlist that now meets the standard, When the help test runs, Then it fails asking to remove that line [check: template/tests/test_help.py.jinja]
- Given failures, When the help test fails, Then its output holds the failing command paths as lines ready to paste into the help allowlist [check: template/tests/test_help.py.jinja]
- Given copier.yml, When it is read, Then tests/help_allowlist.txt is in _skip_if_exists [check: template/tests/test_help.py.jinja]

## How to test

Integration in the generated project: the test walks the real app registry; rule cases use test-only commands on a throwaway Typer app passed to the same check function. The project gate runs it in both include_auth variants.
