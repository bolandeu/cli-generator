A package generated with default answers has only what the Standard makes mandatory: the bare command lists the commands, --version, global --json and the error envelope, doctor, auth status with empty credentials, one example command, its tests, README, AGENTS, the Gitea CI workflow, the install section. Every other part is a copier question: include_project (project config, init, config, status, --project), include_auth with include_providers and include_http_provider, include_db, include_skill (the package's agent skill and its install command), include_describe (describe --json), include_contracts (consumer contracts and detach). A new question defaults to no on copy and yes on update (copier's _copier_operation), so a package made from an older tag keeps every part on copier update; include_auth now defaults to no. A part's code and tests live in its own modules, dropped by _exclude; shared code registers a part only when its module exists (a runtime probe of the module, as auth status and doctor do now), not through Jinja. The docs command, the OpenCLI document and their tests leave the template; the include_ci question goes away and the CI workflow is always generated. The Standard's Optional parts say, for each part, when a package needs it and which question turns it on; the repo README lists the parts the same way. The template gate renders the minimal package, a package with every part, the variants still needed, and the update rounds, and runs rb-release check in each.

## Acceptance

- Given copier copy with default answers, When the package is generated, Then it has the mandatory parts only (no init/config/status/--project, auth login, credentials, providers, database, skill command, describe, contracts, detach, docs) and rb-release check passes [check: sh scripts/check_template.sh]
- Given copier copy with every optional part on, When the package is generated, Then every part is there and rb-release check passes [check: sh scripts/check_template.sh]
- Given a package generated from the previous release tag, When copier update --defaults moves it to this version, Then none of its part files is removed except the docs command and OpenCLI, and rb-release check passes [check: sh scripts/check_template.sh]
- Given the template, When it is searched, Then there is no docs command, no OpenCLI document and no include_ci question, and every generated package has the Gitea CI workflow [check: sh scripts/check_template.sh]
- Given the Standard's Optional parts, When each part is read, Then it names when a package needs it and the copier question that turns it on [check: tests/test_standard_doc.py]

## How to test

Integration through the template gate: copier copy of the minimal and the all-parts variant and the update rounds into temp dirs, then the generated project's own tests and rb-release check. A repo test reads the Standard's Optional parts. Red first: add the minimal and all-parts variants to the gate before cutting the template.

## Basis

Follow how include_auth and include_db already drop files through _exclude and how auth status and doctor probe a module at runtime. AGENTS.md sharp edges: _exclude matches rendered paths; probe the module, never the package; help snapshots are rendered by _tasks.
