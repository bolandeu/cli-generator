The project readme is generated once and never merged on copier update (_skip_if_exists). After copier update --data adopt_core=true it still names scripts/release.py, and the generated test of the gate's callers fails on it; the closing gate of E-004 fails in its update round (FAILED [update-core-true]: test_project_files_name_the_gate_of_their_answer, AssertionError on the readme). The test must check only files the template keeps in sync (antagor.toml, agent guide, coding standards, CI); the readme is the project's. SKILL.md Update mode step 14 gets one line: edit the gate command in the project readme by hand.

## Acceptance

- Given a project generated with adopt_core=false and updated with copier update --data adopt_core=true, When its pytest runs, Then the gate-callers test passes although the readme still names scripts/release.py [check: sh scripts/check_template.sh]
- Given a fresh adopt_core=true project, When the test runs, Then antagor.toml, the agent guide, coding standards and the CI workflow are still checked for the rb-release command [check: template/tests/test_ci.py]
- Given SKILL.md Update mode step 14, When it is read, Then it tells the agent to change the gate command in the project readme by hand, because copier does not update it [check: sh scripts/check_template.sh]

## How to test

Integration via check_template.sh (variant update-core-true).

## Basis

The readme rule in this repo's agent guide (the readme is in _skip_if_exists); step 13 of Update mode handles project-owned files the same way.
