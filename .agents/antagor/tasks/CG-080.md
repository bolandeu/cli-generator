From CG-IDEA-002, the mcp architect.

`x-rb-skills[]` entries carry `name` and `description` today. Add `path`: the filesystem path of the bundled skill directory inside the installed distribution — the directory that holds `SKILL.md` (and, for extra skills, each one its own directory).

Not the install target: `skill install` picks one of `_TOOL_TARGETS[tool][scope]` (`commands/skill.py:47`), which depends on the consumer. The source directory is the only stable answer.

Shape: `{"name": "serp", "description": "...", "path": "/…/site-packages/rb_serp/data/skills/serp"}`.

Get it from the same `_data()` Traversable the module already uses (`core/skills.py:28`): an installed wheel resolves to a real path; a zip import does not — then omit `path` rather than invent one, and say so in the docstring. Empty or absent when `include_skill` is off, as today.

Standard, Describe section: one sentence that each entry names the skill, describes it and points at its directory, so a consumer reads the text with no extra call.

## Out of scope

- deciding where a consumer installs the skill: the target depends on its tool and scope

- deciding where a consumer installs the skill: the target depends on its tool and scope

## Acceptance

- Given an installed package with include_skill on, when describe --json is read, then every x-rb-skills[] entry has a path that exists and holds its SKILL.md [check: template/tests/test_describe.py.jinja]
- Given a package with the skill part off, when describe --json is read, then x-rb-skills is an empty list and no path is invented [check: template/tests/test_describe.py.jinja]

## How to test

System test on the generated package: describe --json, then read each path; unit test on the opencli module with a fixture skill directory bundled and with it absent.
