A release under Antagor pushes one commit to antagor/publish-*, then to main and as tag vX.Y.Z. The template workflow triggers on all three, so every release runs three identical 15-20 min gates on a 2-slot runner; a queued publish-branch run outlasted Antagor's 15 min remote-gate wait and bukvarix's release failed (2026-10-27). The tag's commit is already gated on the publish branch (commit statuses are per SHA), so the tags trigger goes. main stays: hand pushes and merged Renovate PRs need a run there.

## Acceptance

- Given a package generated from the template, When its .gitea/workflows/ci.yml is read, Then on.push has branches [main, antagor/publish-*] and no tags key, and pull_request and workflow_dispatch stay [check: sh scripts/check_template.sh]
- Given the generated package's tests, When test_ci runs, Then it asserts there is no tags trigger instead of asserting tags == ['v*'] [check: sh scripts/check_template.sh]
- Given the template gate's copier update rounds from the previous release tag, When they run, Then the workflow merges without a conflict and the gate passes [check: sh scripts/check_template.sh]
- Given the template gate's name rounds without a hand-written name, When the previous release tag already writes the destination folder as the Antagor name (v1.27.3), Then the round expects the name that tag wrote before the update, not gsc, and passes [check: sh scripts/check_template.sh]

## How to test

Level: integration. Seam: the template gate renders packages, runs their tests and the update rounds. Data: the existing variants.

## Basis

Remove the one line; keep the checkout's fetch-depth 0 (the build reads the version from tags, not the trigger). Update the test assertion in template/tests/test_ci.py. In scripts/check_template.sh, check_name_update's unedited rounds compare the name after the update with the name the previous tag wrote (read it right after generating), so the round holds for tags before and after the antagor_name question; the hand-named rounds keep their explicit name.
