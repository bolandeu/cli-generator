## Problem

A new package gets about 2.8k lines of code and 3.5k lines of tests before its first own command: credentials, providers, project config, package skill, describe, docs/OpenCLI, consumer contracts and detach, needed or not. An agent has to learn and keep all of it. The skill is one long text where a new package and an existing one mix, and its Update mode is a long list of historical migrations.

## Goal

A new package from the template has only what the Standard makes mandatory and passes the gate; each optional part is one copier question, off by default, on when the package needs it. Existing packages lose nothing on copier update. The skill has two modes: new package (template, then gate) and existing package (gate, then fix every red step by the Standard section it names).

## Acceptance (Given–When–Then)

- Given copier copy with default answers, When the package is generated, Then it has only the mandatory parts (the bare command lists commands, --version, --json, the error envelope, doctor, auth status with empty credentials, one example command, tests, README.md, AGENTS.md, Gitea CI, [tool.rb.install]) and none of: project config with init/config/status/--project, credentials and auth login, providers, HTTP provider, database, package skill, describe, consumer contracts, detach; and rb-release check passes
- Given copier copy with every optional part on, When the package is generated, Then every part is there and rb-release check passes
- Given a package generated from the previous release tag with its parts, When copier update --defaults moves it to the new tag, Then none of its parts is removed (except the docs command and OpenCLI, which leave the template), and rb-release check passes
- Given the template, When it is read, Then there is no docs command and no OpenCLI document, and no include_ci question: the Gitea CI workflow is always generated
- Given the Standard's Optional parts, When each part is read, Then it says when a package needs it and which copier question turns it on
- Given the skill, When an agent starts, Then SKILL.md sends it to one of two modes: new package (copier copy with the minimal defaults, turn on only the parts needed, gate green) or existing package (run the gate, fix each red step by the Standard section it names, repeat until green; copier update is not required)
- Given the plugin, When it is validated, Then it is valid

## Implementation decisions

- Optional parts are copier questions: include_project, include_auth (with include_providers and include_http_provider), include_db, include_skill, include_describe, include_contracts (consumer contracts and detach). Each new question defaults to no on copy and yes on update (_copier_operation), so an existing package keeps its files; include_auth defaults to no.
- Code of an optional part lives in its own modules and tests, dropped by copier _exclude; shared files (the root CLI, the doctor, conftest) register a part only when its module exists (runtime probe of the module, as auth status and doctor already do), not through Jinja, so the template stays plain Python.
- The docs command, the OpenCLI document and their tests leave the template; describe --json stays as an optional part (clidocs draws from it).
- The template gate renders a minimal package (defaults), a package with every part, the existing include_auth/publish-only/db variants as still needed, and the update rounds from the previous tag and from the last copy-gate tag.
- The skill: SKILL.md is the order of the agent's actions and the choice of mode; each mode is its own reference file (new package, existing package); the existing-package mode holds the template update steps that are still needed.

## Test seams

- scripts/check_template.sh: generated packages (minimal, all parts, update rounds) and rb-release check in each
- repo tests over the skill files: both modes present, SKILL.md routes to them, Standard section links resolve

## Out of scope

- Applying the template or the gate to existing packages (each package's agent does it on the Human's command)
- New rules in the Standard or new gate steps; clidocs; running the gate on homeserver
