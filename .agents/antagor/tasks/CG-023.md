Every project generated from the template carries a [tool.rb.install] section in pyproject.toml that tells sysadmin's tool-updater where to install it. Two copier questions decide it: the homeserver users to install for (default rbtools; empty = build and publish only) and whether to install on the Mac (default yes). The rendered section has exactly the keys homeserver (list of user names) and mac (bool); extras is documented in a comment only. A comment above the section says what it is for and that installation is sysadmin's. The template gate renders both the default answers and a 'publish only' variant (no users, no Mac). Existing projects get the section with the defaults on copier update: verify once by the git round trip from AGENTS.md (tag, generate, change, copier update --defaults) and report the result in the inbox.

## Acceptance

- Given a project generated with default answers, When its pyproject.toml is parsed with tomllib, Then tool.rb.install == {'homeserver': ['rbtools'], 'mac': True} [check: template/tests/test_cli.py.jinja]
- Given answers homeserver empty and mac false, When the project is generated, Then tool.rb.install == {'homeserver': [], 'mac': False} and its tests pass [check: sh scripts/check_template.sh]

## How to test

Integration: generated project's pytest reads its own pyproject.toml and compares tool.rb.install with the answers in .copier-answers.yml; check_template.sh renders the default and the publish-only variant (add the second variant to its loop alongside include_auth).
