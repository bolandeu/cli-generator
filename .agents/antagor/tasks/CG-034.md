Since the default repository_url is the Gitea repo, the generated readme and the bundled skill render a broken SSH line (git+ssh://git@github.com/https://homeserver…) and GitHub auth advice (gh auth login, gh auth setup-git) that does not apply. Reported by cli-core (fixed there in CORE-004, v0.1.3). For a Gitea repository_url the install is from the Gitea registry: uv tool install <dist_name> --index https://homeserver.tailee01ab.ts.net:3000/api/packages/bolandeu/pypi/simple; the https git line stays. The SSH line and the gh advice render only when repository_url starts with https://github.com/.

## Acceptance

- Given repository_url = https://homeserver.tailee01ab.ts.net:3000/bolandeu/demo, When the project is rendered, Then neither the readme nor the bundled skill contains 'git@github.com' or 'gh auth', and both contain the registry install line with --index https://homeserver.tailee01ab.ts.net:3000/api/packages/bolandeu/pypi/simple [check: template/tests/test_docs_install.py]
- Given repository_url = https://github.com/bolandeu/demo, When the project is rendered, Then the SSH line is git+ssh://git@github.com/bolandeu/demo.git@vX.Y.Z and the gh advice is present [check: template/tests/test_docs_install.py]
- Given repository_url is blank, When the project is rendered, Then the placeholder lines render without a literal Jinja tag [check: sh scripts/check_template.sh]

## How to test

Unit inside the generated project: test_docs_install.py reads its own readme and bundled skill and checks them against the repository_url in .copier-answers.yml; check_template.sh renders the default (Gitea) variant.
