Follow-ups from the reviews of CG-016 and CG-017.
1. The help test parses each Example against the command tree with Click's make_context and resilient_parsing=False, so option callbacks of the command run. The standard says nothing is run. Parse without running callbacks, but still detect unknown options and bad arguments.
2. A non-Click error while parsing an example is reported as 'asks for help or the version'. Report the real exception type and message instead.
3. An allowlist line for a command that does not exist says 'it meets the standard'. Say 'no such command' for that case.
4. The error code EXAMPLE_OUTSIDE_PATH (core/docs ExampleOutsidePath) is missing from the Error codes table of conventions.md. Add it with its exit code and meaning.
5. Reflow the over-long docstring line in core/docs.py to 120 columns.
6. The test_docs fixture gives an enum option a default that is not one of its choices. Use a default that is one of the choices, and keep the exact-line test ('Default: X. Allowed: a, b.').

## Acceptance

- Given a command whose option has a callback that records a call, When the help test parses its Example, Then the callback is not called and the example still passes [check: template/tests/test_help.py.jinja]
- Given an Example with an unknown option --nope, When the help test parses it, Then it still fails naming the command and the example [check: template/tests/test_help.py.jinja]
- Given an option callback that raises ZeroDivisionError while parsing, When the help test runs, Then the failure names ZeroDivisionError [check: template/tests/test_help.py.jinja]
- Given an allowlist line for a command that does not exist, When the help test runs, Then it fails with 'no such command' and the path [check: template/tests/test_help.py.jinja]
- Given conventions.md, When the Error codes table is read, Then EXAMPLE_OUTSIDE_PATH is listed [check: template/tests/test_docs.py.jinja]
