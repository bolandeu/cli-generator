CG-066 let the generated config test accept a package whose Antagor config follows Antagor's advice for mode fast (its own `checks`, the full gate only through `[publish] gate = "remote"` and `heavy`). Another generated test still breaks such a package: `tests/test_ci.py::test_project_files_name_the_gate_of_the_template_tag` asserts the gate command is among `checks`. The fast-mode variant of the template gate script missed it because it ran only one test file.

1. The CI test accepts the gate either among `checks` or as the remote gate (`[publish] gate = "remote"` with a status URL); it still asserts the agents file and the coding standards name the gate of the template tag, and that no release script is left.
2. The fast-mode variant of the template gate script runs the package's whole test suite, not one file.

## Acceptance

- Given a package rendered from the template whose Antagor config has fast-mode checks without the gate command, worker = "claude-code" and the remote gate, When its whole test suite runs, Then it passes [check: sh scripts/check_template.sh]
- Given a package rendered from the template with its default Antagor config, When its tests run, Then they pass [check: sh scripts/check_template.sh]

## How to test

The template gate script: its fast-mode variant rewrites the rendered Antagor config the way a fast-mode package does and runs the whole suite.

## Basis

Follow how CG-066 relaxed the config test in the generated test of scripts: the gate in checks, or the remote gate with its status URL.
