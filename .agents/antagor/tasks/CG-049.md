A new mode file for an existing CLI or package (from the template or not). The loop: run the gate (the uvx rb-release check command at the template tag); for each red step, open the Standard section the failure names, fix the package, run again, until it ends with 'release: gate passed'. copier update is not required to meet the Standard. Then the optional sections, short: bringing a script or CLI that is not a package yet onto the Standard (what is still true of today's Refactor mode and refactor checklist, merged, no history); a package made from the template that wants template updates (the clean-tree rule, the staged update script for a worker that may not commit, conflict resolution, refreshing help snapshots, the gate line in the package's Antagor config, switching from a copied release script to the uvx gate, renaming the distribution). Drop migration steps for template versions no package needs any more; keep each remaining step's commands exact. SKILL.md is rewritten by a sibling task and only names this file: do not edit it.

## Acceptance

- Given the existing-package mode, When an agent follows it, Then the first step runs the uvx gate at the template tag and the loop fixes each red step by the Standard section it names until the gate passes, with copier update not required [check: tests/test_skill_existing.py]
- Given a package on an older template, When the mode's update part is followed, Then it reaches the uvx gate: clean tree, copier update (or the staged script), the old release script and rb-cli-core gone, the gate line in the package's Antagor config checked, help snapshots refreshed, gate green [check: tests/test_skill_existing.py]
- Given the mode file, When every Standard section it links is looked up, Then each exists in the Standard, and the file names none of adopt_core, uv run rb-release, release.py --check, the docs command or include_ci as something to do [check: tests/test_skill_existing.py]
