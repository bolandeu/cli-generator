## Problem

The Human reads CLI help in a browser via InSpectra, but the template's describe nests commands under 'command', keeps examples and option text inside descriptions and shows every option as repeatable, so InSpectra renders an empty or unreadable page; there is no written help standard and no test of it.

## Goal

Every generated CLI has '<cli> docs': a deterministic OpenCLI document InSpectra renders into a readable HTML page; the help standard lives in reference/help-standard.md and a test enforces it on every command, with a project allowlist for old commands; describe stays the same machine contract plus arity.maximum.

## Acceptance (Given–When–Then)

- Given a generated project, When '<cli> docs' runs, Then stdout is an OpenCLI JSON document with opencli, info, commands, options, arguments, examples at the root, and every template command is present
- Given a command whose docstring has 'Example: <cli> <path> ARGS' and an optional '-> RESULT' line, When docs runs, Then that command's examples field holds 'ARGS' or 'ARGS  # -> RESULT' and the description has no Example line
- Given an Example line that does not start with '<cli> <command path>', When docs runs, Then it exits 1 with an error naming the command and the example, and writes no document
- Given an option with a default and/or fixed allowed values, When docs runs, Then the last line of its description is exactly 'Default: X. Allowed: a, b.' (each part only when it applies; a flag shows 'Default: off.'), and a non-repeatable option has arity maximum 1
- Given docs run twice on the same code, When the outputs are compared, Then they are byte for byte the same; Given --out FILE, Then the same bytes go to FILE and stdout is empty; Given an unwritable --out path, Then the standard error envelope with a non-zero exit and no partial file
- Given a CLI with a hook that adds inherited options, When docs runs, Then those options appear once, recursive, on the parent; positional arguments are never inherited
- Given describe --json, When compared with the previous snapshot, Then the only change is arity.maximum 1 on non-repeatable options
- Given a command that breaks the help standard (no one-line summary, no Example, an option without help, an option's text repeated in the description, an Example that does not parse against the command tree), When the help test runs, Then it fails naming the command and the rule, unless the command is listed in tests/help_allowlist.txt
- Given an existing project after copier update, When its help test fails, Then the test output lists the failing commands ready to paste into tests/help_allowlist.txt, SKILL.md Update mode says so, and copier update never overwrites that file
- Given the gate, When check_template.sh runs for both include_auth variants (and include_db), Then docs and the help tests pass in the generated project without dotnet or InSpectra

## Implementation decisions

- core/docs: generic module taken as one snapshot from semkit (release after SEMKIT-058): Click-tree walk shared with core/opencli, docstring split (summary, description, option lines, examples), Default/Allowed line, arity, example prefix strip, optional hook for inherited options
- commands/docs: new top-level command next to describe, --out FILE, standard global options and error envelope
- core/opencli: describe output unchanged except arity.maximum 1 for non-repeatable options
- tests/test_help: help standard checks over the command registry; tests/help_allowlist.txt is a project file in copier _skip_if_exists
- reference/help-standard.md: the standard moved from semkit's draft, neutral wording; architecture.md and conventions.md point to it; SKILL.md Update mode gets the crossing step

## Test seams

- '<cli> docs' through the CLI runner in the generated project (JSON read back and checked)
- the help contract test (test_help) over the command registry
- the describe snapshot test (test_describe)

## Out of scope

- The clidocs tool (a separate project, scaffolded after this release)
- Running examples and checking their results (a project's own runner, like semkit SEMKIT-055)
- InSpectra or dotnet in tests, CI or on homeserver (Mac only)
- Any other change to describe; describe in CLIs that lack it (their own repos)
- clidocs --all
