Every package where Antagor has updated its own files gets a red CI: the template's scripts test asserts that the package's Antagor ignore file holds exactly `state/` and `receipts/`, and Antagor now also writes `scratch/` there (and may add more). That file is Antagor's, not the template's: Antagor owns everything under its folder except the config with the package facts.

1. The template stops shipping Antagor's ignore file; copier's exclude list names it, so `copier update` leaves the copy a package already has as it is (Antagor keeps it current), and a new package gets it from Antagor.
2. The template's test no longer asserts anything about Antagor-owned files; it keeps checking the package facts of the Antagor config.
3. The Antagor prefix question takes what Antagor takes: a capital letter, then 1-11 capitals or digits (`[A-Z][A-Z0-9]{1,11}`, e.g. `MEDIAGEN`, `SITEGEN`), not only 2-4 letters; its help says "task prefix", not "ticket prefix"; the default stays as it is. A package whose answers file has a long prefix passes `copier update`.
4. The template gate shows it: a rendered package whose Antagor ignore file has an extra line (as Antagor writes it) passes its tests, and a copier update round leaves that file as it was.

## Acceptance

- Given a package rendered from the template whose Antagor ignore file holds `state/`, `receipts/` and `scratch/`, When its tests run, Then they pass [check: sh scripts/check_template.sh]
- Given a package made from the previous release tag with that ignore file, When `copier update` runs to this tree, Then the file is unchanged and no conflict appears [check: sh scripts/check_template.sh]
- Given a new package rendered from the template, When its files are listed, Then the template wrote no Antagor ignore file and the Antagor config is there [check: sh scripts/check_template.sh]

- Given the answer `antagor_prefix=MEDIAGEN`, When the template is rendered and then updated, Then both pass the validator and the Antagor config has `prefix = "MEDIAGEN"`; `mg` or `1AB` is refused [check: sh scripts/check_template.sh]

## How to test

The template gate script: render, append `scratch/` to the Antagor ignore file the way Antagor does, run the suite; its update round checks the file survives. The previous-tag round matters: exclude patterns added after a release use `is false`-style care (see the sharp edges in the repo's agent notes) so the old render keeps the file.

## Basis

Follow the existing exclude list in copier's config and the update-round checks in the template gate script.
