The release gate moves from the separate cli-core repo into this repo, and the template stops copying it. In gate/ lives a Python package (distribution and command rb-release) with the gate's code and tests moved from cli-core (its gate module, its CLI, the release tests, the gate parity cases and their fixture projects). It runs over the package in the current directory, exactly as rb-cli-core 0.1.x does: same step names, last line and exit codes. A package needs nothing added to run it: `uvx --from "git+https://homeserver.tailee01ab.ts.net:3000/bolandeu/cli-generator.git@<tag>#subdirectory=gate" rb-release check`.

No Standard step here: the step list stays exactly 0.1.x; the next task (CG-043) adds the Standard steps in gate/standard/.

The template no longer copies scripts/release.py and has no adopt_core question: CI, antagor.toml, AGENTS.md and README run the uvx command pinned to the template tag of the project (the `_commit` of .copier-answers.yml); the dev dependency on rb-cli-core and its gitea source go away. A project updated from v1.20.10 (adopt_core true or false) loses its copy or its rb-cli-core dependency and runs the gate the new way. An edited copy is not kept or turned into a conflict: it is deleted, and the package's edits stay in its git history (a package agent ports them through a ticket). The template gate runs the gate from the working tree of this repo (a local path in place of the git URL), so a change to gate/ is tested with the template.

## Acceptance

- Given gate/ with the moved tests, When they run, Then the release tests and the gate parity cases pass unchanged (step names, last line, exit codes as rb-cli-core 0.1.x) [check: sh scripts/check_template.sh]
- Given any project, When `uvx --from <this repo>#subdirectory=gate rb-release check` runs in it, Then the gate runs and the project's pyproject and uv.lock are untouched [check: sh scripts/check_template.sh]
- Given a project rendered from this template, When its files are read, Then there is no scripts/release.py, no adopt_core in .copier-answers.yml, no rb-cli-core anywhere, and CI, the antagor checks, AGENTS.md and README call the uvx command with the tag of `_commit` [check: sh scripts/check_template.sh]
- Given projects generated at v1.20.10 with adopt_core=false and with adopt_core=true, When each is updated to this template through the worker script, Then the copy or the dependency is gone and the new gate passes [check: sh scripts/check_template.sh]
- Given every template variant (auth, no auth, publish-only, db), When the template gate runs, Then each passes the gate run from this working tree [check: sh scripts/check_template.sh]

- Given the template's AGENTS and package skill files, When they are read, Then they link the Standard by its Gitea URL (skills/cli-builder/reference/standard.md on main) and cite named sections, not § numbers [check: sh scripts/check_template.sh]

## How to test

Integration: the template gate (copier copy/update into temp dirs, then the gate from the working tree's gate/). gate/'s own pytest suite runs from the template gate's repo-tests step. Red first: the template gate expects no scripts/release.py before the template changes.

## Basis

Move, do not rewrite: cli-core's gate module, CLI, release tests and parity tests (with their fixture projects) are the behaviour. The adopt_core switch of E-004 shows every place the gate is named (copier.yml, pyproject template, CI workflow, antagor.toml, AGENTS.md, README, check_core_adopted in the template gate).
