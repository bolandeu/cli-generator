## Problem

Both rows come from the CG-082 extraction (docs/research/2026-11-08-plan-extraction.md, F4.4 and F4.9). The db part ships items/responses example tables inside the package's own tables.py, so copier update merges them in as duplicates; check_command_docstrings.py compares node.args whole, so adding ctx to a signature reads as changed logic and fails a docstring that is still true. Each costs a package agent a hand fix today.

## Goal

A generated package carries no example tables inside its own core/tables.py, and the docstring checker does not treat a ctx-only signature change as a logic change.

## Acceptance (Given–When–Then)

- Given a package generated with the db part on, when its core/tables.py is read, then it holds the package's own tables only, with no example table merged in by an update
- Given a command whose signature gains only ctx, when check_command_docstrings.py runs, then it passes without touching the docstring
