The Human decided (2026-10-23) that a project's name in the Antagor config is always its folder name, never the CLI command name. The template writes the command name, so google-search-console became "gsc" and yandex-direct "yd", and Plane and the Antagor registry show the wrong project. A package's folder name is also its Gitea repository name (google-search-console, yandex-direct, serp).

Known facts, checked on a throwaway copier template: during `copier update`, `_copier_conf.dst_path` is a temporary directory (`copier._main.new_copy.<random>`), or `.` when `copier update` runs without a destination argument. It is a PurePosixPath, so `.resolve()` does not exist. A name taken from it at update time is wrong. A question's answer is kept in `.copier-answers.yml` and comes back on every update.

## Acceptance

- Given `copier copy` with `repository_url=https://homeserver.tailee01ab.ts.net:3000/bolandeu/google-search-console` and `cli_name=gsc` into a folder named `demo-folder`, When the package is generated, Then the Antagor config has `name = "demo-folder"`, and a copy into `.` inside `demo-folder` gives the same [check: sh scripts/check_template.sh]
- Given a package generated before this change with `repository_url` ending in `rb-dataio` whose Antagor name was set by hand to `dataio`, When `copier update` runs, with or without a destination argument, Then the name stays `dataio` and the config has no conflict [check: sh scripts/check_template.sh]
- Given a package generated before this change that never edited the name line, When `copier update` runs, with or without a destination argument, Then the line is unchanged: never a temporary directory name, `.`, or a name taken from `repository_url` [check: sh scripts/check_template.sh]
- Given the update instructions, When a package's name differs from its folder, Then they say the update never changes the name and the package edits the line once by hand, which later updates keep [check: sh scripts/check_template.sh]

## How to test

Level: integration. Seam: copier copy/update in the template gate. Data: the existing variants, plus one with `cli_name` and `repository_url` both different from the folder name, plus update rounds from the previous release tag, run with and without a destination argument.

## Basis

`repository_url` is the GitHub mirror and its name can differ from the folder (dataio: `rb-dataio`), so it is not a source of the name. On copy the name is the destination folder's; on update (`updating`) the default renders what the old template rendered (`cli_name`), so the three-way merge keeps the package's line (ADR 0014 pattern).

## Feedback

### Attempt 1: the Architect's verdict

repository_url is the GitHub mirror, not the Gitea repo, and its name can differ from the folder: dataio has repository_url https://github.com/bolandeu/rb-dataio, folder and Gitea repo 'dataio', Antagor name 'dataio'. With this branch the next unattended Renovate 'copier update' silently renames it to rb-dataio (old render 'dataio' == project line, new render 'rb-dataio' -> applied without conflict). All 15 existing packages already have name = folder name, so an update must not change the line at all. Fix: (1) antagor_name default: when 'updating' -> {{ cli_name }} (identical to what the old template rendered, so the merge keeps whatever the package has, hand-fixed names included); else -> the destination folder name (_copier_conf.dst_path | realpath | basename). Do not derive it from repository_url at all. (2) Gate: copy with repository_url=.../google-search-console and cli_name=gsc into folder demo-folder -> name demo-folder; copy into '.' stays; update rounds: a package with repository_url .../rb-dataio and the name hand-set to 'dataio' keeps 'dataio' with no conflict, in place and with a destination argument; a package that never edited the line keeps its name (no tmp dir, no '.'). Drop the cases that expect the update to take the name from repository_url. (3) existing-package.md: the update never changes the name; a package whose name differs from its folder edits the line once by hand (the update keeps it). Keep the CG-077 coverage line untouched.

### Answer to finding #1

> CG-076 left gate_status_url as it was (out of scope): it still derives the repository name from repository_url by its own rule (no .git strip) and falls back to cli_name when repository_url is blank.
