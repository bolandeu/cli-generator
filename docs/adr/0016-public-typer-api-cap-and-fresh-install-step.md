# Глобальные опции частей — только публичный API Typer, `typer <0.29`, шаг гейта `fresh install`

Статус: accepted (Человек, 2026-11-13; задача CG-091).

12 из 19 пакетов на Mac, установленных заново (`uv tool install`, проверено 2026-11-12), падали на импорте с
`TypeError: TyperOption.__init__() missing 1 required keyword-only argument: "type_descriptor"`. Причин две, обе в
шаблоне: код пакета сам создавал внутренний `typer.core.TyperOption` в `commands/project.py` (`--project`) и
`commands/skill.py` (`--ai`), а `pyproject.toml` держал только `typer>=0.12`, так что новая минорная версия typer
приезжала при следующей установке. Ограничение версии само по себе класс не лечит: код обязан перестать трогать
внутренности typer, а следующий подъём зависимости должен ловить гейт, а не новая машина через месяцы.

Решили:

1. Часть объявляет глобальную опцию функцией-объявлением — `def _global_options(project: str | None =
   typer.Option(..., expose_value=False, callback=_remember_project)) -> None` — и кладёт её в
   `output.RootGroup.part_options`; `RootGroup` монтирует объявление на временное приложение и читает параметры
   через `typer.main.get_command`. Внутри typer строит параметр из сигнатуры сам, поэтому шаблон живёт только на
   публичном API. Подкласс группы берётся оттуда же — `from typer.main import TyperGroup`: `cls=` с подклассом
   `TyperGroup` — документированная точка расширения, её 0.29 не менял, а имени `typer.core` в шаблоне не остаётся.
2. `template/pyproject.toml.jinja` держит `typer>=0.27,<0.29`. Нижняя граница — версия, на которой проверен весь
   пакет; верхняя — 0.29, где ломается уже не рантайм, а собственная обвязка шаблона: `tests/test_help.py` зовёт
   `param.type_cast_value` и `param.get_error_hint`, а click внутри typer 0.29 поменял и то, и другое. Пакет со всеми
   частями зелёный целиком на 0.27.3 и 0.28.0.
3. Гейт получил шаг `fresh install`: установка в пустую среду, где зависимости разрешаются из индекса, как на новой
   машине. Шаг сборки колеса ставит ровно набор `uv.lock` и никогда не разрешает зависимости — поэтому он был зелёным,
   пока ломался каждый свежий `uv tool install`. Для инструмента `--version` печатает выпускаемую версию, `--help`
   работает; для библиотеки импортируются все пакеты верхнего уровня. Каталог инструментов — во временной папке
   гейта, каталог пользователя не трогается.

Рассмотренные варианты: оставить только ограничение версии (класс не лечится — внутренний вызов ломается при
следующей правке typer); поднять typer до 0.29 и править тесты шаблона сейчас (отдельная задача: рантайм на 0.29
работает, ломается тестовая обвязка); позволить Renovate поднимать нижнюю границу по зелёному шагу `fresh install`
(диапазон держится живым: ограничение ставят один раз и снимают, когда гейт согласен).
