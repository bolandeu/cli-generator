Since v1.24.0 is released, the template gate's update round from the previous release tag generates a package from v1.24.0 itself, where the optional parts are copier questions that default to no. The round then requires every part to be present after copier update and fails ('commands/project.py of the part project is missing'), so the gate is red on main and nothing can be published. The round must check what an update may not do: remove a file the package had (beyond the files the template drops on purpose) or lose a part the package had. For a tag before the part questions every part counts as on, for a tag with them the package's answers decide. Generate the previous-tag package with every optional part on whenever that tag has the questions, so the round still proves that an update keeps all parts.

## Acceptance

- Given the previous release tag has the part questions, When the update round runs, Then the package generated there with every part on keeps every part after copier update and the round passes [check: sh scripts/check_template.sh]
- Given the copy-gate tag v1.20.10 (before the part questions), When its update round runs, Then every part is present after copier update and the docs command is gone [check: sh scripts/check_template.sh]
- Given an update that removes a file the package had and the template does not drop on purpose, When the round runs, Then it fails and names the file [check: sh scripts/check_template.sh]

## How to test

Integration through the template gate itself: run it on main (red now), then green after the fix.

## Basis

check_update_round, generate_at and expect_parts as they are; ADR 0014 for how a part is on for an older package.
