The release gate of a generated project checks the [tool.rb.install] section of its pyproject.toml, so no package is released without a valid install declaration. Valid: the section exists; homeserver is a list of non-empty strings (may be empty); mac is a bool; extras, if present, is a list of strings; no other keys. On failure the gate stops with one line that names the key and the expected shape, and for a missing section prints the section to add (the default one). A valid section passes with a short ok line like the other gate steps.

## Acceptance

- Given pyproject.toml without [tool.rb.install], When the install-section check runs, Then it fails with a message containing 'tool.rb.install' and the default section text [check: template/tests/test_scripts.py]
- Given mac = "yes", When the check runs, Then it fails naming 'mac' and 'bool' [check: template/tests/test_scripts.py]
- Given homeserver = "rbtools" (a string, not a list), When the check runs, Then it fails naming 'homeserver' and 'list of user names' [check: template/tests/test_scripts.py]
- Given an unknown key target = 1, When the check runs, Then it fails naming 'target' as unknown [check: template/tests/test_scripts.py]
- Given homeserver = [] and mac = false, or homeserver = ['rbtools'], mac = true, extras = ['x'], When the check runs, Then it passes [check: template/tests/test_scripts.py]
- Given a freshly generated project (both include_auth variants), When release.py --check runs, Then the gate passes [check: sh scripts/check_template.sh]

## How to test

Unit: call the new check function of release.py on tmp pyproject.toml files (the way test_scripts.py already loads release.py); integration: the template gate command.

## Basis

release.py: _tool() reads [tool.*], fail() is the gate's failure; follow check_external_deps for the step shape and its ok line.
