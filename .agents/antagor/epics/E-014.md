## Problem

Rows F7.1 and F5.2 of the CG-082 extraction. Under pytest-xdist the contract step prints '[gw0] [ 50%] PASSED tests/test_contracts.py::test_contract[x]', which _CONTRACT_RESULT does not match, so the step reports '0 cases' — pass/fail still comes from the return code, so only the text lies, and a package author wastes a run on it. In the template, core/errors.py ships DatabaseUnavailable, DatabaseNotMigrated and DatabaseTooNew in every package, including packages generated without the db part, where nothing can raise them.

## Goal

A package's contract step reads its summary under pytest-xdist, and the Database errors ship only with the db part — so neither a green suite looks broken nor a package carries errors it cannot raise.

## Acceptance (Given–When–Then)

- Given a package that runs its contracts under pytest-xdist, when the gate prints the contract step, then the summary counts the cases instead of reporting 0
- Given a package generated with include_db false, when core/errors.py is read, then it holds no Database error, and with the db part on it does

- the gate output of a rendered package and scripts/check_template.sh
