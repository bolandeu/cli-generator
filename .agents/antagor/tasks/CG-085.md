The Human, 2026-11-08: CI is either remote or local, not both — and it is local.

1. Standard, CI (and Release where it repeats the point): the gate is rb-release check run on the machine that builds the package; Gitea stores releases and nothing else. Remove the Mandatory rule that a workflow under .gitea/workflows/ runs the gate, and the Recommended bullet about one job on the docker runner. Keep the hard part: a release exists only after a green gate.
2. Standard, Docs: if a rule points at the workflow, it now points at the local gate command.
3. SKILL.md, Update mode: a package updated to this tag deletes .gitea/workflows/ci.yml (copier removes what the template no longer renders — the template task proves it; if it does not, this mode says it by hand). Say it once, where an agent reads it before updating.
4. docs/adr/00XX-the-gate-is-local.md: the decision, its dates (the Human, 2026-10-29 and 2026-11-08), what it replaces (the remote workflow, gate_status_url, template-gate.yml), and what it costs (a break is found by the next local gate, not by a push).
