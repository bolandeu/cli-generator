Docs only. Rewrite architecture.md §1 'Distribution' so it describes how packages actually reach machines today, as a fact owned by sysadmin (not by this repo):
- Repo pushed to Gitea (bolandeu, public, tailnet only), mirrored to GitHub.
- sysadmin's tool-updater on homeserver: on each new vX.Y.Z tag of a repo listed in its tools.toml (tools and libs) builds the wheel and publishes it to the Gitea PyPI registry https://homeserver.tailee01ab.ts.net:3000/api/packages/bolandeu/pypi (simple index: .../pypi/simple); trigger: tag refs on disk + hourly timer. A repo not in tools.toml is not published. It installs tools.toml entries with 'uv tool install --index gitea=<registry>/simple rb-x==V' (rb-* only from Gitea, the rest from PyPI).
- Reading the registry needs no token. Use the ts.net host, never 127.0.0.1.
- Manual install from the registry: uv tool install --index gitea=https://homeserver.tailee01ab.ts.net:3000/api/packages/bolandeu/pypi/simple rb-<name>. The GitHub mirror git+ install still works off the tailnet.
- Owners pinning a dependency to the registry: pattern in sysadmin repo docs/tool-updater.md 'Регулировка версий'.
- Rule for this repo: it does not change, publish to or configure the registry or tool-updater; a new tool is added there by telling sysadmin (as §1 already says).
Keep the rest of §1 (gh auth, first push, telling sysadmin) consistent; remove the 'no PyPI required / install from the GitHub mirror' framing where it now contradicts the facts. Do not touch template/ or §8.
