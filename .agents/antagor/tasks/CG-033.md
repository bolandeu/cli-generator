Every place of a generated project that runs the gate calls 'uv run rb-release check' when the project takes the gate from rb-cli-core, and 'uv run scripts/release.py --check' otherwise: the Gitea CI workflow, the antagor checks, the project's agent guide, coding standards and readme, the consumer contracts doc and schema. The CI workflow stays a plain file: it chooses by the presence of scripts/release.py.

## Acceptance

- Given adopt_core=true, When the project's CI workflow, antagor.toml and agent guide are read, Then they run uv run rb-release check and nothing names scripts/release.py [check: template/tests/test_ci.py]
- Given adopt_core=false, When the same files are read, Then they are byte-identical to the previous template release [check: sh scripts/check_template.sh]
- Given the CI workflow, When it runs in a project without scripts/release.py, Then its gate step runs uv run rb-release check, and with the script it runs the script [check: template/tests/test_ci.py]

## How to test

Integration: test_ci.py inside the generated project reads its own files for the answer it was rendered with; check_template.sh renders both variants.

## Basis

Jinja conditionals on adopt_core in .jinja files; a shell test in the plain CI file.
