SKILL.md Update mode step 14.2 tells a worker that may not commit to always run copier_update_staged.py, but the script refuses a clean tree (exit 2). A worker that starts step 14 in a fresh worktree has a clean tree and stops. The script must not refuse a clean tree: with nothing staged it is a plain copier update. General step 1 of Update mode then says nothing about a clean-tree refusal, so the worker has one command and no branch to choose.

## Acceptance

- Given a generated project with a clean, committed tree, When a worker runs copier_update_staged.py --trust --defaults --vcs-ref HEAD, Then the update runs and exits 0, not 2 with 'tree is clean' [check: sh scripts/check_template.sh]
- Given a generated project with a staged, uncommitted change, When the script runs, Then the update is done and the change is kept, as in v1.20.8 [check: sh scripts/check_template.sh]
- Given SKILL.md Update mode, When general step 1 is read, Then it has no clean-tree refusal and gives one worker command for every update step [check: sh scripts/check_template.sh]

## How to test

Integration through the template gate: one update round (e.g. update-defaults) goes through the script on a clean tree; the round with the staged change stays. Red first: the clean-tree round fails while the refusal is there.
