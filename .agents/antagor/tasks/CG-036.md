From semkit SEMKIT-065 (IDEA-266) and the check of semkit v0.1.53: Update mode is written for someone who can commit and edit every file. An Antagor worker can do neither, and two things broke:

1. Update mode (general step 1, steps 13.1, 14.1) says "commit, then `copier update`". The worker hook forbids `git commit`, and copier has no flag to skip its dirty-tree guard (copier 9.19.1, `Subproject.is_dirty` checked in `run_update`). The semkit worker improvised: `git add -A`, then `copier.run_update` from Python with the guard off. Copier builds its merge base from the index (`git write-tree`), so a staged tree loses nothing.
2. semkit v0.1.53 shipped with `.agents/antagor/antagor.toml` `checks` still calling `uv run scripts/release.py --check` after step 14 removed the script. The task owned `antagor.toml`, not `.agents/antagor/antagor.toml`, and step 14.3 says the file "now calls" the new gate as if the update always does it. Its own tests (`test_ci.py`, `test_scripts.py`) then fail from a clean clone.

Do:

- Add `skills/cli-builder/scripts/copier_update_staged.py`: a ready command for a worker that may not commit. It stages the tree (`git add -A`), refuses to run if the index is empty of changes AND the tree is clean (then plain `copier update` is the way), runs copier's update with every argument passed through (`--vcs-ref`, `--data k=v`, `--defaults`, `--trust`, `--pretend`) and only the dirty-tree guard off, and exits non-zero on any copier error. Run it as `uvx --from copier python <skill dir>/scripts/copier_update_staged.py [args]` (state the exact command in SKILL.md). Keep it small; it touches copier internals in one place, with a comment naming the copier version it was checked against.
- `scripts/check_template.sh`: one update round (e.g. `update-core-true`) makes an uncommitted, staged change first (switch `_src_path` in `.copier-answers.yml` to the same source written another way, or edit a project file), then updates through the new script instead of plain `copier update`, and checks the change survived. So a copier release that breaks the script breaks our gate, not the packages.
- SKILL.md Update mode: general step 1, 13.1 and 14.1 — "commit" stays for a session that can commit; a worker stages and uses the script (exact command). Step 14.3 (and 13 where it applies): `.agents/antagor/antagor.toml` `checks` must name the gate of the answer (`uv run rb-release check` with adopt_core); check it after the merge, `grep -n checks .agents/antagor/antagor.toml`. In a task for a worker the Architect puts `.agents/antagor/antagor.toml` in owns_paths, or edits it before the run — say which (the file the template ships, not a root `antagor.toml`).
