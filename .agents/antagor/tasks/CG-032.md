The skill and the standard describe the core library and the switch. Scaffold passes adopt_core=true for new packages. Update mode gets a numbered step for an existing package: copier update --trust --defaults --data adopt_core=true, check scripts/release.py is gone, uv lock, uv run rb-release check, release; what to do if the package had edited its copy of release.py (port the change into rb-cli-core through a ticket to cli-generator, never keep a local copy). architecture.md §8 says the gate is rb-release check from rb-cli-core (or the copied script while adopt_core is false) and links ADR 0010 and docs/plans/cli-core.md.

## Done when

1. SKILL.md Scaffold command has --data adopt_core=true.
2. SKILL.md Update mode has the numbered switch step with exact commands and the rule for an edited copy.
3. architecture.md §8 and the AGENTS.md of this repo name both gate forms and link ADR 0010.
4. claude plugin validate . --strict passes.
