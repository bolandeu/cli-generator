# План: простой шаблон и единый Стандарт

Источник: разговор с Человеком 2026-10-20. Шаблон разросся (~2,8 тыс. строк кода и ~3,5 тыс. строк тестов в новом
пакете до первой своей команды; требования разнесены по `architecture.md`, `conventions.md`, `help-standard.md`,
`SKILL.md`). Цель Человека — не размер, а простой для любого агента шаблон с записанными требованиями: технология,
команды, ошибки, документация и т. д. Пакет может немного отходить.

Принцип (Человек): скилл и шаблон упрощают разработку и поддержку пакетов, а не усложняют их. Каждое правило,
часть шаблона и шаг скилла проверяются этим вопросом.

## Решения (Человек, 2026-10-20, по рекомендации)

1. Шаблон — минимальный каркас; остальное — необязательные части, включаются, если нужны.
2. Требования двух видов: «обязательно» (проверяет гейт) и «рекомендуется» (пакет может отойти).
3. Все требования — в одном документе «Стандарт»; `SKILL.md` — только порядок действий агента.
4. Пакет самостоятелен: работает на любой машине без агента, плагина и нашей инфраструктуры; для работы — только
   зависимости из PyPI (Человек, 2026-10-20). Слой вывода и ошибок — маленький код в пакете. `rb-cli-core` —
   только инструмент разработки (гейт `rb-release check`), не runtime-зависимость. Эпик CG E-005 снят; CORE E-002
   (0.2.0) уже выпущен, его модулями пользуется только `rb-release`.
5. Скилл `cli-builder` — два режима: новый пакет (шаблон → проверка) и существующий (проверка → починить красное).
6. Привести пакет к Стандарту = `rb-release check` зелёный. Проверка называет каждое нарушение обязательного правила;
   переезд существующих пакетов на шаблон через `copier update` не требуется. Каждое обязательное правило проверяется
   машиной, иных обязательных нет.
7. Гейт переезжает в этот репозиторий (`gate/`), репо `cli-core` и его проект закрываются. Пакет берёт гейт
   зависимостью разработки из `cli-generator` по тегу шаблона (`git+…@<_commit>#subdirectory=gate`): шаблон и гейт —
   одна версия, `copier update` двигает обе. Команда — `rb-release`. Модули вывода 0.2.0 не нужны.
8. `clidocs` остаётся отдельной личной смотрелкой Человека (Mac), вне Стандарта. Команда `docs` и opencli уходят из
   шаблона; `clidocs` рисует из `describe --json` (необязательная часть, рекомендуется).
9. Стандарт заморожен: новое правило — только если без него пакет реально ломается.

## Порядок

1. Стандарт + проверка обязательных правил в `rb-release check`.
2. Минимальный шаблон.
3. Скилл в двух режимах.
4. Применение: агент каждого пакета прогоняет проверку и чинит красное (по команде Человека).

## Документ «Стандарт» (Человек, 2026-10-20, по рекомендации)

Английский; один файл `skills/cli-builder/reference/standard.md` вместо `architecture.md`, `conventions.md`,
`help-standard.md` (чек-лист рефакторинга — в скилл, длинные обоснования — в ADR); `AGENTS.md` пакета ссылается на него
адресом в Gitea, без копии; ссылки на разделы — по названию, не «§N».

## Обязательно (гейт)

- Технология: Python, uv, Typer; дистрибутив `rb-<slug>`; версия из git-тега; установка из реестра Gitea;
  `[tool.rb.install]`.
- Команды: `<cli>` без аргументов — список команд; `--help` у каждой; `--version`; справка по стандарту справки.
- Вывод: `--json` у каждой команды, конверт; stdout — данные, stderr — диагностика.
- Ошибки: коды и коды выхода по таблице; неожиданная ошибка — тоже в JSON.
- `doctor --json` и `auth status --json` в фиксированной форме (контракт с sysadmin); без ключей `auth status` —
  пустой список.
- Ключи не в репо и не в аргументах.
- Тесты, гейт `rb-release check`, CI в Gitea зелёные; есть `README.md` и `AGENTS.md`.

## Необязательные части (у каждой — когда нужна, как включить, её требования)

- Проект: `.<package>/config.toml`, `init`, `config`, `status`, `--project`.
- Ключи (`auth`): если есть — env `<CLI>_<PROVIDER>_<FIELD>`, провайдеры в `auth status`.
- Провайдеры и HTTP.
- База данных (PostgreSQL, SQLAlchemy, Alembic, `db`).
- Скилл пакета (для инструментов, которые агенты зовут из других проектов): описание «когда брать», установка,
  особенности; общие правила — один раз, не в каждом пакете.
- `describe --json` (по нему рисует `clidocs`).
- Контракты потребителей, `detach`.

## Связь с планом ядра
